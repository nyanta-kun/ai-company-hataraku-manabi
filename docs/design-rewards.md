## 0. 結論（先に）

> **追記（2026-10-26）**: でんしゃ の棚に 5 種（はやぶさ・こまち・かがやき・どくたーいえろー・りにあ）を足して **でんしゃ は 12 種、全体は 47 種（S0 は 43 種）**。以下の 42・38 などの数は追加前のもの。決定と注意は 6.3。

1. **棚 6 つ・42 種**: はたらくくるま 11（今のまま）／まちの くるま 8／でんしゃ 7／そら 6／うみ 6／きゅうじょたい 4（S1 以上。今のまま）。今ある乗り物の絵 15 種をカードにし、**12 種を描き足す**。
2. **ゲーム → 棚**: かず→はたらくくるま、もじ→まちの くるま、とけい→でんしゃ、えいご→そら、かく→うみ。S1 以上はどのゲームでも きゅうじょたい も候補。
3. **抽選**: `pickReward(owned, scene, rng, rank, game)`。`game` を渡さない（または棚の無い）呼び出しは**今の関数と完全に同じ**。かず は、はたらくくるま（＋救助隊）がそろうまで今と同じ乱数で同じ車。順番は「自分の棚の未入手 → ほかの棚の未入手（いちばん集まっていない棚）→ 自分の棚の★ → ほかの棚の★ → ステッカー」。
4. **保存**: 形は変えない。`CAR_IDS` を 15 → 42 に増やすだけ。旧版に戻す件は「読めるようにする PR を先に出す」で防ぐ。
5. **R4**: `isCards` の件数の上限（15 → 42）と正規表現 1 本を直す。正規表現は 1 つの文字列なので**式の数は増えない見込み**。試験 13 を回し直して確かめる。`p.icon` は 15 種のまま。
6. **PR**: ① 絵と音 → ② データ・保存・抽選・ルール（画面は変えない）→ ③ しゃこの棚と呼び出し側。

## 3. 抽選（`src/rewards.js`）

### 3.1 形

```
pickReward(owned, scene, rng, rank, game)   // game 省略可。戻り値は今と同じ { id, stars, isNew } | { sticker: true }
applyReward(cards, scene, rng, rank, game)  // 今と同じく cards を書き換えず、新しい cards を返す
```

- `game` が `D.GAME_SHELF` に無い（省略・未知の名前）ときは、**今の 15〜36 行の処理をそのまま通す**（`legacy`）。1 文字も変えない。`tests/rewards.test.js` と `tests/rescue.test.js` は**そのまま全部通る**ことが、この経路の回帰試験になる。
- 呼ぶ側（`src/ui.js`）は PR-3 から必ず `game` を渡す（5 章）。PR-2 の時点では `game` を渡していないので、画面の出方は変わらない。

### 3.2 手順（`game` に棚があるとき）

言葉の定義:
- `rescue = (rank | 0) >= D.RESCUE_FROM`
- **pool**（候補の全体）: すべての棚の乗り物。`rescue` でなければ きゅうじょたい の棚を除く（S0 は 38 種、S1 以上は 42 種）
- **home**（自分の棚）: `GAME_SHELF[game]` の棚の乗り物。`rescue` なら きゅうじょたい の 4 種を後ろに足す
- 並びは常に `SHELVES` の順・棚の中の順（同じ乱数で同じ結果にするため。3.3）

```
1. pool に持っているものが 1 つも無い → { id: 'shoubousha', stars: 1, isNew: true }   （今の :21 と同じ）
2. U = pool の未入手
   2a. H = home の未入手（home の順）
       H がある:
         - home が hataraku: near = SCENE_CARS[scene] ＋（rescue なら RESCUE_SCENE_CARS[scene]）のうち H にあるもの（near の順）。
           near があれば pick(near)、無ければ pick(H)        ← 今の :25-27 と同じ式・同じ順
         - それ以外: その棚（救助隊を除く）に持っているものが無く、顔が H にあれば 顔。そうでなければ pick(H)
         → { id, stars: 1, isNew: true }
   2b. H が無い（自分の棚と救助隊がそろった）: 溢れ
         - 未入手のある棚のうち、「持っている数 ÷ 棚の数」がいちばん小さい棚（同じなら SHELVES の順で並べて pick）
         - その棚で 2a と同じ決め方（hataraku なら現場の優先、ほかは顔を先に）
         → { id, stars: 1, isNew: true }
3. open = pool で ★ < 3 のもの。無ければ { sticker: true }
   base = open のうち home にあるもの。無ければ open
   base の★の最小 → その★の乗り物から pick → { id, stars: ★+1, isNew: false }
```

- `pick(arr, rng)` は今と同じ（`rng()` を 1 回だけ呼ぶ。`src/rewards.js:10`）。顔を選ぶときは `rng` を呼ばない。
- 2a の「顔」は棚の最初の 1 枚だけ（その棚の乗り物を 1 つも持っていないとき）。はたらくくるま の顔 しょうぼうしゃ は手順 1 が先に出すので、2a では使わない（今の出方を変えないため）。
- 溢れ（2b）の割合の比べは、浮動小数を避けて `持っている数 × 相手の棚の数` の掛け算で比べる。

### 3.3 「今と同じ」の範囲（はっきり決める）

| 呼び方 | 今の版と比べて |
|---|---|
| `game` 省略・未知 | **完全に同じ**（同じコード）。11 種（S1 以上 15 種）★3 でステッカー |
| `game = 'math'`、S0（rank 0） | はたらくくるま 11 種を全部持つまで、**同じ `owned`・同じ乱数の並びなら同じ戻り値**。そろった後は、今は★を増やすところで、ほかの棚の未入手が来る |
| `game = 'math'`、S1・S2 | はたらくくるま＋救助隊の 15 種を全部持つまで同じ。その後は上と同じ |
| `game` がほかのゲーム（S0 も） | 変わる（自分の棚から出る）。1 回目が しょうぼうしゃ なのは同じ。rank 0 で救助隊が出ないのも同じ |
| 全部 ★3 のあと | 今は 11 種（15 種）★3 でステッカー。新しい版は pool 全部が ★3 になるまでステッカーにならない |

- 「同じ戻り値」の条件: `owned` の中で、pool に入る id が はたらくくるま（と救助隊）だけで、しょうぼうしゃ を持っていること（`{}` から ごほうびを重ねた状態はいつもこれを満たす）。`owned` に まちの くるま などだけがある作られた状態では、手順 1 の判定が今と違う（今は しょうぼうしゃ、新は 2a）。ふつうの遊び方では起きない。
- 同じ戻り値にするには、home の並びを `CARS` の順＋`RESCUE_CARS` の順にし（今の `ids`。`src/rewards.js:19`）、near の並びを `SCENE_CARS[scene].concat(RESCUE_SCENE_CARS[scene])` の順にする（`:25`）。並びを変えると、同じ乱数でも違う車が出る。

### 3.4 どの棚にも属さない場合

- **乗り物**: `ALL_VEHICLES` の全部が、`SHELVES` のちょうど 1 つの棚に入る（試験）。棚に無い id は抽選に出ない。
- **保存にある、棚に無い id**: 起きない（`CAR_IDS` と `ALL_VEHICLES` を一致させる試験。8.1）。
- **ゲーム**: `D.GAMES` と `'trace'` の全部が `GAME_SHELF` にある（試験）。6 つめのゲームを足して棚を決め忘れると試験が落ちる。確認用の呼び出し（`game` 省略）は今の出方になる。

### 3.5 捨てた案

| 案 | 捨てた理由 |
|---|---|
| 棚ごとにステッカー（自分の棚が ★3 なら、ほかの棚があってもステッカー） | そのゲームを遊ぶ理由が消える。「必ず 1 枚」が実質ステッカーだけになる |
| 自分の棚しか出さない（溢れなし） | 1 つのゲームだけ遊ぶ子・えいご が遊べない端末（`src/ui.js:1307`）の子は、ほかの棚が永久に埋まらない |
| 「自分の棚の★」を「ほかの棚の未入手」より先に | かず だけ遊ぶ子は 33 回同じ棚が続く（企画 4 章の偏り）。今の「未入手を先に」（`docs/plan.md:166-167`）とも合わない。企画 9 章の確認点 3 |
| 溢れは未入手の全体から一様に選ぶ | 大きい棚（はたらくくるま 11）に寄る。いちばん集まっていない棚から選ぶほうが偏らない |
| 確率で混ぜる（自分の棚 2/3・ほか 1/3） | 子どもにも保護者にも説明しにくく、試験もしにくい。ガチャに近い |
| 救助隊を かず の棚だけに入れる | 今の S1 の子は どのゲームでも救助隊が出る。それを狭める理由が無い |
| `game` 省略を「かず」と同じにする | 今の試験（11 回で全種・33 回でステッカー）が全部書き換えになり、回帰の比べる相手（今の関数）が消える |

## 4. しゃこの画面（`src/ui.js`・`index.html`・`css/style.css`）

### 4.1 見せる棚

- `visibleShelves()`: `SHELVES` のうち、`from` が無い棚と、`from` があって「解放済みのステージ ≥ from、または その棚の乗り物を 1 つでも持っている」棚（今の `garageCars()` の決まり。`src/ui.js:903-906`）。S0 の子は 5 つ、S1 以上は 6 つ。
- **救助隊の枠は S0 の子に見せない**（design-elementary 3.12 の決定のまま）。棚ごと出さない。
- ほかの 5 つの棚は、S0 の子にも**まだの枠をシルエットと「？」で全部見せる**（今と同じ見せ方。`src/ui.js:920`, `:942`）。ほかのゲームに誘うのが目的なので隠さない。

### 4.2 見出しと棚の切り替え（iPhone SE 375×667 の縦で 1 行）

```
[もどる] [のりもの][もじ]                       ← 見出し（今の .bar。480px 以下は「しゃこ」の文字を消す。今のまま）
```
