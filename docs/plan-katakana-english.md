## 1. 目的・対象・範囲・完了条件

### 目的
- カタカナ: 働く車の名前はカタカナが多い（ダンプカー、ブルドーザー、パトカー等）。好きな車を足がかりに、ひらがなの次の文字としてカタカナの形と音を結びつける。
- えいご: 好きな車を足がかりに、英語の音（fire truck、ambulance、1〜10）に触れ、「聞いて選ぶ」ことで耳を慣らす。読み書きは教えない。

### 対象ユーザー
- 主: 4〜6歳。字はほぼ読めない前提（plan.md と同じ）。英語は聞く中心。
- 副: 保護者（レベル確認・固定、音のオン/オフ、英語の声の確認）。

### 守る原則（plan.md 1章と同じ）
字が読めなくても操作できる／失敗状態なし（1回目の誤答で無効化、2回目でヒント、必ず正解して進む）／1回4問／声が出なくても進める（ただし英語は 3.4 の例外）／ごほうび・現場・自動昇降級は既存のまま。

### やること
0. 「もじ」の単語表を、乗り物と消防を中心に大きく増やし（ひらがな 31語・カタカナ 17語）、同じ語が偏らない出題規則を入れる（2.3・2.9）。必要な新規の絵 23 個は共通リストにし、えいご E1 でも使う（2.8）。
1. 「もじ」にカタカナ段階 K4〜K6 を追加（2章）。
2. ミニゲーム「えいご」を4つめに追加。段階 E1〜E3（3章）。
3. 出動えらびを4択にし、保存データ・保護者画面を拡張（4章）。
4. 問題生成・昇降級を純粋関数で実装し、`scripts/test.sh` でテスト（2.5・3.6）。

### やらないこと（今回）
- カタカナ・英語の書き・なぞり、英語の綴りを読ませる／書かせる出題、小文字、筆記体。
- 頭文字が拗音・外来音・長音符・促音・「ん」の語の出題（しょうぼうしゃ、しょうかき、ショベルカー、フォークリフト等。plan.md U1 と同じ扱い。U12 で別形式を検討）。第2文字以降に長音がある語（ばす、だんぷかー、ろーどろーらー等）は、頭文字が明確なので出題してよい。
- 「あ行」「わ行」「な行」を埋めるための、乗り物・消防と関係の薄い語の追加（U13）。
- 英語の文（「This is a bus」等）、英語の音声ファイルの同梱（読み上げは端末の `speechSynthesis` のみ）。
- 外部画像・外部音声・通信・課金。Web 公開（下の承認事項）。
- 子ども向け UI 文言へのカタカナ・英語の導入（2.6）。

### 完了条件
9章の受け入れ条件をすべて満たし、純粋関数のテストが通り、reviewer のレビューを経て main に PR 経由でマージされていること（ローカルで遊べる状態まで。公開は含まない）。

### 人間の承認が必要なもの
- **Web 公開・外部公開**（実施前に承認）。
- 有料サービスは使わない前提。本企画に課金は含まない。
- （承認ではなく方針の確認）英語の読み上げに**端末外（ネットワーク経由）の声**が使われると「通信ゼロ」が崩れる。3.3 のとおり端末内の声を優先し、端末外の声を使うかどうかは未決事項 U6 で決める。

## 2. もじ に カタカナを含める

### 2.1 案の比較と決定

K6 の決め事:
- **1問の中で選択肢の文字種はそろえる**（答えが「だ」なら選択肢は全部ひらがな、「ダ」なら全部カタカナ）。「だ」と「ダ」を同時に出すと、読み上げが同じなので正解が2つになるため。
- 文字種は、出題する語の表記で決まる（ひらがな語→ひらがなの選択肢、カタカナ語→カタカナの選択肢）。
- 1回の出動（4問）に、ひらがな語とカタカナ語を**少なくとも1問ずつ**含める。
- 同じ乗り物（同じ絵）を、ひらがな表記・カタカナ表記で1回の出動に2度出さない（「だんぷかー」と「ダンプカー」は同じ絵のため）。

### 2.3 単語表の拡充（`data.js`。ひらがな 31語・カタカナ 17語）

依頼: 「もじの質問のパターンが限られている。乗り物・消防を中心に増やす」。現状は 8語（`WORDS`。そのうち絵が乗り物なのは6語、頭文字は 8種）。これを、**乗り物と消防を中心に、ひらがな 31語（頭文字 26種）・カタカナ 17語（頭文字 14種）**に増やす（合わせて 48問題、目標 30語以上を満たす）。

作り方:
- 1つの語を「マスター」として持ち、外来語（カタカナで書くのが自然な語）には**カタカナ表記を併記**する。ひらがな表（K1〜K3）はマスター全部、カタカナ表（K4〜K6）は「カタカナ表記」が○の語。**同じ語は同じ絵（`pic`）を使う**。
- 表記はカタカナのまま、**読み上げ（`speech`）はひらがな**（既存 `WORDS` の `label` / `speech` / `example` と同じ作り）。
- `wordId` は表ごとに一意（カタカナ版は `_k` を付ける。例 `dump`／`dump_k`）。
- 頭文字（`head`）は `label` の**最初の1文字**で、清音・濁音・半濁音。拗音（ゃゅょ）・外来音の小書き（ぁぃぅぇぉ）・長音符・促音・「ん」で始まる語は使わない。2文字目以降に長音符・拗音がある語（ばす、だんぷかー、ゆうびんしゃ）は頭文字が明確なので使ってよい。

### 2.4 形が似た文字の扱い

- 表記は変えない（シ/ツ、ソ/ン、ク/ケ はそのまま出す）。**読み上げはひらがな読み**（2.3 の `speech`、`example`）で、形の違いは子どもが目で見分ける。
- `CONFUSABLE_KATA`（追加）: ク–ケ、ダ–タ、ブ–プ、バ–パ、ポ–ホ、ポ–ボ、ホ–ボ、ヘ–ベ、ト–ド、シ–ツ、ソ–ン（ソ–ン は語が無いため MVP では使われない）。
- `CONFUSABLE`（ひらがな。既存の6組に追加）: ば–ぱ、ぽ–ほ、さ–き、で–て、ろ–る、ふ–ぶ。**ひらがなの頭文字は 26種に増えたので、追加文字（頭文字にならない相手）は不要**（既存の「単語表にある文字のみ誤答に使う」のまま。両方が頭文字にある組＝は–ほ、だ–た、ば–ぱ、ぽ–ほ、ふ–ぶ、さ–き が実際に混ざる。ね–ぬ・み–め・ご–こ・ぶ–ぷ・ろ–る・で–て は相手が頭文字に無いので混ざらない。テストで「相手が頭文字にある組だけが混ざる」ことを確かめる）。
- **カタカナの選択肢の候補文字は、カタカナ語の頭文字14種＋追加文字**にする。頭文字: ダ・ブ・ホ・シ・ロ・タ・バ・オ・サ・ポ・ヘ・ク・ト・パ。追加文字（頭文字にならないが、まぎらわしい相手として出す）: ケ、プ、ボ、ベ、ド、ツ。追加文字にも例語を持たせる（ケ→けーき、プ→ぷりん、ボ→ぼーる、ベ→べんち、ド→どあ、ツ→つみき）。選択肢をタップしたときの読み上げ「{例語}の {ひらがな}」に使うため。
- シ/ツ は、シンカンセン（シ）を入れたので**出題できる**（相手のツは追加文字）。ソ/ン は、採用語に頭文字がなく、「ン」始まりの語は無いので、**MVP では出題として扱えない**（U3）。
- **実装の注意**: `data.js` の `ROW` はひらがな（8文字）だけなので、**ひらがな 26種とカタカナ 14種＋追加文字 6種の行を追加する**（行は清音・濁音・半濁音を別キーにしてよいが、2.9 の「は行」の制限は清音・濁音・半濁音をまとめた「行ファミリー」で数える。ROW とは別に `FAMILY` を持つ）。ブ/バ、ホ/ヘ は同じ行ファミリーなので、K4 の2択でこの組は同時に出ない。ブ/バ、ホ/ヘ は同じ行なので、K4 の2択でこの組は同時に出ない。`confusableOf` は現在 `CONFUSABLE` だけを見るので、カタカナの問題では `CONFUSABLE_KATA` を見るようにする。
- K5 では、まぎらわしい組の相手を最大1つ混ぜてよい（既存の K3 と同じ。半分の確率）。K4 では混ぜない。
- 選択肢の誤答は、**現問題の語の頭文字と一致しない**（バ／パ はどちらも頭文字だが、パトカーの問題で「バ」が出るのは誤答として正しい）。
- 読み上げの崩れ（「へ」が助詞「え」と読まれる等）は plan.md R2 と同種のリスクで、例語方式（「へりこぷたーの へ」）で緩和し、実機で確認する。

### 2.5 問題生成（`problems.js`）への影響

```
LEVELS.letter = ['K1','K2','K3','K4','K5','K6']
LETTER = { ..., K4:{choices:2, script:'kata'}, K5:{choices:4, script:'kata'}, K6:{choices:4, script:'mixed'} }
generateLetter(level, rng, prevWordId, avoid)  // 戻り値に script:'hira'|'kata' と pic を追加。avoid は 2.9 の除外条件（省略可）
generateSession('letter', level, rng, recentPics)   // K6 は 2.2 の制約、全レベルで 2.9 の規則を満たす4問。recentPics は保存データの直近の絵（省略時は空）
nextLevel('letter', ...)                // 上限を K6 に
```

テストで検証する性質（既存の性質1〜9に**追加**。固定シードで各レベル1000問以上）:
1. K4/K5 の `answer` はカタカナ語表の頭文字と一致。`script==='kata'`。選択肢は全てカタカナ。
2. K6 の選択肢は `script` と同じ文字種だけ（ひらがなとカタカナが混ざらない）。`answer` と同じ音の別文字種の文字（例 だ と ダ）が選択肢に入らない。
3. 選択肢の長さは K4=2、K5=4、K6=4。`answer` がちょうど1つ。重複なし。
4. K4 の選択肢は互いに行が異なり、`CONFUSABLE_KATA` の組を含まない。
5. K5/K6(カタカナ問題) で、まぎらわしい組の相手が混ざるのは最大1つ。非正解の選択肢は現問題の語の頭文字と一致しない。
6. K6 の `generateSession` は、ひらがな語・カタカナ語を各1問以上含み、同じ絵（`pic`）を2度含まない。
7. `wordId` は両表を通して一意。同じ `wordId` が1回の出動に重複しない。同じ問題が連続しない。
8. 同じシードなら同じ結果。
9. `nextLevel('letter', ...)` が昇降級の規則に従い、上限 K6、下限 K1。固定時は変えない。範囲外の現在値は端に丸める。
10. データの整合: 全語の `head` が `label` の先頭1文字と一致（拗音・長音符・促音・「ん」で始まらない）。各選択肢文字に `example` がある。ひらがな読み `speech` が全てひらがな（長音符「ー」は可）。ひらがな表 31語・カタカナ表 17語。全語の `pic` が `vehicles.js` に存在する（絵が無い語を出さない）。`cat` が定義済みの値。K1 の出題元 A 群は 14語。
11. （偏り防止・同一出動。`recentPics` なしで検証。緩和が起きない前提）固定シードで各レベル 1000 出動以上: 4問の中で、`wordId`・`pic`・答えの文字（`answer`）が重複しない。「は行」ファミリーは最大1問、その他の行ファミリーは最大2問。（K1 は A 群 14語のみで成立すること。）
12. （偏り防止・連続出動）`recentPics` に直近 N 枚の絵を与えると、その絵の語は出ない（N は 2.9）。候補が足りないときは古い順に解禁し、**空の出動や無限ループにならない**。`recentPics` に未知の値・重複・配列以外が入っていても落ちない。
13. （均等さ）200 出動を連続で生成し、`recentPics` を引き継いだとき、各レベルの出題元の全語が1回以上出て、最多の出現回数÷最少 ≤ 4（実装後に実測して調整）。K1〜K3 で2連続の出動に同じ `pic` が出ない。
14. （分類）出題元に `cat` が 2 種類以上ある出動では、同じ `cat` が 3問を超えない。消防（`fire`）と、道路・電車・空の乗り物が、K3・K5・K6 の出動に少なくとも1問ずつ含まれる（出題元に両方ある場合）。

### 2.9 出題の偏り防止（同じ語ばかり出ない規則）

「もじの質問のパターンが限られている」への対策として、単語表の拡充（2.3）に加えて次の規則を `generateSession('letter', ...)` に入れる。**純粋関数**のまま、直近の履歴は引数（`recentPics`）で受け取り、保存は呼び出し側（ui.js・storage.js）が行う。

**A. 1回の出動（4問）の中**（全レベル K1〜K6 共通）
1. 同じ語（`wordId`）を2度出さない。**同じ絵（`pic`）を2度出さない**（ひらがな・カタカナの別表記も同じ絵なので同じ扱い）。
2. **同じ答えの文字を2度出さない**（ひ：ひ／ひこうき、ば：ばけつ／ばす 等の同頭文字の語が同じ出動に入るのを避ける）。
3. **同じ行ファミリー**（清音・濁音・半濁音をまとめた行。は行＝は・ひ・ふ・へ・ほ・ば・び・ぶ・ぱ・ぽ 等）は、**は行は最大1問、その他の行は最大2問**。は行が語表の4割を占めるため（2.3）。
4. **同じ分類（`cat`）は最大3問**。出題元に消防（`fire`）と乗り物（`road`/`rail`/`sky`/`sea`/`work`）の両方がある K3・K5・K6 では、それぞれ少なくとも1問含める。
5. K6 は 2.2 の規則（ひらがな語・カタカナ語を各1問以上）も満たす。
6. 4問を選べない（制約が強すぎる）ときは、**4 → 3 → 2 の順に制約を外す**（4＝分類の上限と「消防・乗り物を各1問」、3＝行ファミリーの上限、2＝答えの文字の重複禁止）。**1（同じ語・同じ絵の禁止）は外さない**。空の出動や無限ループにしない（試行回数に上限を置く）。

**B. 連続する出動の間**
1. 直近に出した絵（`recentPics`。新しい順に最大 12 個）を除いて抽選する。除外する数 N は `N = min(12, floor(出題元の絵の数 ÷ 2))`、下限 4。例: ひらがな 31語は N=12（候補 19）、カタカナ 17語は N=8（候補 9）、K1（A 群 14語）は N=7（候補 7）。
2. 候補が 4 未満になるときは、**古い順に除外を解く**（N を減らす）。
3. 直前の出動の最後の語は、次の出動の最初に出さない（既存の「同じ問題が連続しない」を出動をまたいで保証）。
4. **記録のタイミング**: 出動が始まって問題が確定した時点で、その 4つの `pic` を `recentPics` の末尾に足し、12個を超えた分は古いほうから捨てる。途中でやめても、出した語は「見た」とみなす。
5. 昇降級でレベルが変わっても履歴は引き継ぐ（絵で数えるので、ひらがな⇄カタカナを越えても同じ絵が連続しない）。

**C. 保存**（`storage.js`）: `hataraku-manabi:v1` に任意の項目 `seen: { letter: ['v10', 'airplane', ...] }` を足す（バージョンは 1 のまま）。`normalize` で、配列でない値は `[]`、文字列以外・未知の絵 id・重複は捨て、12個に切る。保存データが無い・壊れていても、出題は 2.9-A だけで成立する。えいご E1 でも、同じ仕組みを `seen.english` に使える（PR-C で検討）。

**D. 検証**: 2.5 の性質 11〜14。

### 2.10 しゃこ（ごほうびカード）に新しい乗り物を加えるか

現状は 11種×★3＝33ステップ（1日1〜2回の出動で約3週間）。

**推奨: 加える。ただし働く車・救助の車 6種だけを、別 PR（B4）で、もじの拡充より後に。**
- 加える 6種: **パトカー、バス、トラック、クレーン車、ロードローラー、ヘリコプター**。理由は「はたらく車」という世界観に合い（plan.md の目的）、現場にも絡められる（michi＝クレーン・ロードローラー・トラック、takai＝ヘリコプター、まち＝パトカー・バス）から。17種×★3＝51ステップ（約5週間）で、飽きる前に新しい車が出る。

- MVP（B1〜B3）にはしゃこの変更を含めない。もじと えいご の拡充を先に出す。

### 3.3 読み上げ（`speech.js` への影響）

現状の `speech.js` は、日本語の声だけを選び（`pickVoice`）、`lang='ja-JP'` 固定、日本語の声が無いと全体を「声なしモード」にする。英語のために必要な変更:

1. **言語ごとの声の選択**: `voices = { ja, en }` を持つ。`pickVoice` は言語ごとに選ぶ。
   - ja: 既存どおり（`/^ja/`、端末内優先）。
   - en: 優先順は「en-US かつ localService」→「en-* かつ localService」→（U6 で許可する場合のみ）「en-US の端末外」→「en-*」。macOS には `en-US` でも効果音のような**ノベルティボイス**（Bells、Zarvox 等）が混ざるので、名前の除外リストを持ち、通常の声を選ぶ。実機で確認（U7）。
2. **`speak(text, opts)` に `opts.lang`（'ja' | 'en'）を追加**。`en` のときは `u.lang='en-US'`、`u.voice=voices.en`、`rate` は日本語より遅め（0.8 前後、U7 で実機調整）。既定は 'ja'（既存の呼び出しは変えなくてよい）。
3. **連続読み上げ**: 「Fire truck!」→「しょうぼうしゃは どれ？」のように英語と日本語を続けて読む必要がある。`speakSeq([{text, lang}, ...], opts)` を追加し、`onend` でつなぐ。途中で `cancel` または次の発話が来たら、`seq` で古い連鎖を無効にする（既存の仕組みと同じ考え方）。
4. **声なし判定を言語別に**: 今の `failed` は日本語の判定。英語の声が無いことで日本語の読み上げを止めてはいけない。`enAvailable()` を別に持つ（`speechSynthesis` があり、英語の声が見つかり、英語の発話開始が連続2回失敗していない）。`init()` 後の1.5秒で英語の声も探す。`voiceschanged` で復帰。`onChange` を英語の状態変化でも通知。
5. **`noStart` は言語ごとに数える**（英語だけ開始しない端末で、日本語が巻き込まれないように）。
6. `forceVoiceless()` に加えて、`#debug` 用に `forceNoEnglish()`。
7. テスト: `create(env)` に偽の env を渡して、(a) 言語別の声の選択、(b) 英語の声が無くても日本語は available、(c) `speakSeq` の順序とキャンセル、を `tests/speech.test.js`（新規）で確認する。design.md では speech.js は「目視」だったので、ここは**テストを足す**提案。

### 3.4 英語の声がないときの扱い

声なしでは英語の「聞いて選ぶ」が成立しない（絵を見て答えがわかるだけで、英語の学習にならない）。そのため日本語（声なしでも国語は進める）と扱いを変える。

- **英語の声が使えないとき、出動えらびの「えいご」ボタンを選べなくする**（グレーに薄くし、小さなスピーカー×を重ねる）。タップすると「えいごの こえが ないよ」と読み上げ（日本語の声が使える場合）＋ おしい音。出動は始まらない。
- 判定は、出動えらびを開くたびに最新の状態を見る（後から声が来たら選べるようになる）。
- 保護者画面に「えいごの こえ: つかえる／みつからない」を表示し、テストボタンで確認できるようにする（5章）。見つからない場合の案内（端末の設定で英語の音声を追加する、など。OS ごとの手順は書かない）を出す。
- **出動の途中で英語の声が失敗した場合**（開始イベントが来ない等）は、その出動は続行する。画面には英語の単語を**小さく字幕**で表示し、国語の声なしと同じく**1回目の誤答で正解を光らせる**。出動後は上の判定で「えいご」を選べなくなる。
- 日本語の声が無く英語の声だけあるときは、えいごは選べる（日本語の補助文は読まれないが、英語＋絵／数で成立する）。

### 3.5 世界観・遊び方・読み上げ台本

出動の流れ・現場・ごほうびは既存のまま。出題は「消防署の無線から英語が聞こえる」演出（任意。MVP では演出なしでもよい）。

| 場面 | E1（乗り物） | E2・E3（かず） |
|---|---|---|
| 画面 | 現場の中央に大きなスピーカーのアイコン。答えは乗り物の絵ボタン | 現場の中央にスピーカーのアイコン。答えは数字＋ドット |
| 出題 | 「Fire truck!」→（短い間）→「しょうぼうしゃは どれ？」 | 「Three!」→「さんは どれ？」 |
| 選択肢タップ | その乗り物の英語（「Ambulance」） | その数の英語（「Five」） |
| 1回目の誤答 | 「おしい！もういちど」（その選択肢を無効化） | 同左 |
| 2回目の誤答／残り1つ | 正解の絵が光り、「Fire truck?」→「こっちかな？」 | 正解が光り、「Three?」→「こっちかな？」 |
| 正解 | 「そう！ Fire truck！」 | 「そう！ Three！」→ 数のものが1つずつ出て「one, two, three」（1回の読み上げ） |
| 声なし（途中失敗時） | 英語を小さく字幕表示。1回目の誤答で正解を光らせる | 同左 |

- 日本語の補助は「どれ？」程度に短く。英語だけで通じる子は日本語を待たず答えてよい。
- 日本語の「さん」は E2/E3 では数の日本語読み（よん・なな・きゅう）。時刻の読みとは別（plan-clock.md 4.2 と混ぜない）。
- 子ども向け UI のラベルは「えいご」（ひらがな）。英語の単語は読み上げが主で、字幕は途中失敗時だけ。

### 3.6 問題生成（純粋関数・テスト対象）

```
generateEnglish(level, rng, prevKey)  // level: 'E1'|'E2'|'E3'
  -> E1: { kind:'english', level, form:'word', wordId, en, ja, choices:[wordId...], answer:wordId }
  -> E2/E3: { kind:'english', level, form:'number', n, en:'three', choices:[number...], answer:n }
generateSession('english', level, rng)   // 4問
nextLevel('english', current, firstTryCorrectCount, locked)   // LEVELS.english = ['E1','E2','E3']
```

- E2/E3 の数の選択肢は既存の `numberChoices`（正解±1〜2優先）を再利用。
- 既存 `sameProblem` に `english` の分岐を足す（`wordId` または `n` で比較）。**足さないと clock と同じ理由（両方 undefined で常に同じ問題）で `generateSession` が空回りする**ので必須。

テストで検証する性質（固定シード、各レベル1000問以上）:
1. `choices` に `answer` がちょうど1回含まれ、重複がない。長さは E1=3、E2=3、E3=4。
2. E1: 全ての `choices` が `ENGLISH_WORDS` の id。同グループの語が同時に出ない。
3. E2: `n` と数の選択肢が 1〜5。E3: 1〜10。0・負数・範囲外なし。
4. 数の誤答は正解±1〜2を優先し、足りない分は範囲内の他の数で補う（既存の性質4と同じ）。
5. `en` が `ENGLISH_WORDS` / `NUM_EN` の値と一致する。`ja` が全てひらがな。
6. `generateSession('english', ...)` は4問で、同じ問題が連続しない。E1 は同じ語を1回の出動で重複させない（6〜14語中4問）。E2 は同じ数を重複させない（5通り中4問）。E3 は可能な限り重複させない。
7. 同じシードなら同じ結果。
8. `nextLevel('english', ...)` が規則どおり（上限 E3、下限 E1、固定時は不変、範囲外は端に丸める）。
9. 対象語が出題台本に使える（`en` が空でない、小文字の英字とスペースだけ）。

## 10. 実装順と PR 分割（推奨）

前提: **とけいのマージ後に着手する**（PR-A の向きの修正も先にマージされていること）。とけいが `problems.js`・`data.js`・`storage.js`・`ui.js`・`index.html`・出動えらびを広く変更しているため、同時に進めると衝突する。着手時は、とけいのマージ後の main から作業ブランチを切り、`LEVELS`・`sameProblem`・保護者画面の配列の最新の形に合わせる。

**推奨: PR-A（別担当）→ PR-B1 → PR-B2 → PR-B3 → PR-C。しゃこの拡張 PR-B4 は任意。**

0. **PR-A: 乗り物の向きの修正**（別担当。**この企画の対象外**）。B1 の絵の向きの規約が決まるので、**B1 は PR-A のマージ後に着手**する。
1. **PR-B1: 新規の絵（2.8 の 23個）**
   - `vehicles.js` に N01〜N23 を追加し、`drawPic` が新しい id を引けるようにする（`v` で始まらない id）。`#debug` に全絵の一覧パネル。データ・出題・保存は変えない。
   - 見た目だけの変更なので、reviewer は「絵が見分けられる・実在のマークがない・既存の絵が変わっていない」を見る。
   - 大きいとき（目安: 差分が大きすぎて1回のレビューで見切れない）は、**B1a 道路の車 8個（N06・N08・N14・N18・N19・N20・N22・N23）／B1b 空・水・レール 7個（N01〜N05・N07・N21）／B1c 小物 8個（N09〜N13・N15〜N17）** に分けてよい。B2 は「絵が揃った語だけ」を単語表に入れられる（絵が無い語は出さない。性質10）。
2. **PR-B2: ひらがなの単語表の拡充＋出題の偏り防止（K1〜K3）**
   - `data.js`（`WORDS` を 31語、`cat`・`group`、`CONFUSABLE`・`ROW` の追加）→ `problems.js`（2.9 の規則、`recentPics`）とテスト（性質 10〜14 のひらがな分）→ `storage.js`（`seen.letter`）とテスト → `ui.js`（出動開始時に `recentPics` を渡して更新）。
   - **これで依頼「もじの質問を増やす」が単独で実現する**（カタカナを待たなくてよい）。出動えらび・`speech.js` は変えない。
3. **PR-B3: カタカナ（K4〜K6）**
   - 順に: カタカナ表（17語・追加文字・例語・`CONFUSABLE_KATA`・`FAMILY`）→ `problems.js` とテスト（性質1〜9、10〜14 のカタカナ分）→ `ui.js`/`scenes.js` の表示 → `storage.js`（`levels.letter` の範囲・`kata`）→ 保護者画面 → `#debug`。
4. **PR-B4（任意）: しゃこに働く車 6種を追加**（2.10）。B3 の後でも前でもよい。保存・ごほうび・棚の変更を含むので独立させる。
5. **PR-C: えいご**
   - 順に: `speech.js` の言語対応（`speakSeq`、言語別判定）とテスト → データ（語・数。E1 は B1 の絵も使う）と `problems.js`・テスト → `storage.js` → 出動えらびの4択化（レイアウト・アイコン）→ `ui.js`/`scenes.js` → 保護者画面（声の状態・テスト）→ `#debug`。
   - 4つめのボタンと `speech.js` の変更を含む。全ミニゲームの音声に関わるので、日本語のテストが通ることを必ず確認する。

分ける理由:
- 影響範囲が違う。絵（B1）は見た目だけ、単語表と偏り防止（B2）は `problems.js`・保存、カタカナ（B3）は同じ `problems.js` の拡張、えいご（C）は `speech.js`（全ゲームの共通部）と出動えらび。混ぜると、レビューで見るべき点が散り、問題の切り分けも難しい。
- **B2 を B3 より先にするのは、依頼の中心（乗り物・消防の語を増やす）が、カタカナなしで届くため**。B3 の語はひらがな表のマスター（2.3）を土台にするので、B2 の後が自然。
- 当初案の「PR1 カタカナ（新規の絵5つを含む）」は、絵が 23個に増えたため、B1（絵）・B2（ひらがな）・B3（カタカナ）に分けた。
- えいごを先に見たいときは、PR-C を B1 の後ろに入れ替えてよい（E1 は既存6語だけでも成立する）。その場合も 2 つ以上の PR に分ける。PR-C のうち `speech.js` だけを先に独立 PR にする（さらに1分割）案もある。工数が増えるので、通常は分けない。
- 各 PR で `reviewer` を通してから main へ。実機（iOS Safari・Android Chrome）の読み上げ確認（U7）は PR-C のマージ前に行う。
- 承認: 各 PR の main へのマージは通常の流れ（PR 経由）。Web 公開・外部公開は含まず、別途承認が要る。
