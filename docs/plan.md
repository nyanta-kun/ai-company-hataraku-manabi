# hataraku-manabi 企画書

作成: 企画部 / 状態: ドラフト（社長室レビュー待ち）/ 対象フェーズ: MVP

## 1. 目的・ターゲット・範囲

### 目的
消防車を中心とした「はたらく車」が好きな就学前の子が、国語（ひらがなの読み）と算数（かぞえる・たしざん）を、遊びの延長で飽きずに続けられるブラウザ学習アプリを作る。

### 対象ユーザー
- 主: 4〜6歳（年中〜年長）。字はほぼ読めない前提。1人でも触れる。
- 副: 保護者。子どもの進み具合を確認し、音のオン/オフを切り替える。

### 設計の大原則
1. **字が読めなくても全操作ができる**: ボタンはアイコン中心、説明は音声（読み上げ）＋アニメで伝える。画面の文字はひらがなのみ（漢字なし）で、読めなくても進行に影響しない。
2. **失敗状態なし**: ゲームオーバー・減点・タイマー切れはない。間違えたらやさしいヒント→もう一度。必ず最後は正解して進む。
3. **短い**: 1回の「しゅつどう（出動）」は4問（約2〜3分）。終わりが必ず来て、ごほうびがもらえる。
4. **音声が出なくても進む**: 読み上げが使えない端末でも、効果音とアニメだけで進行できる（5章・11章参照）。

### やること（MVP）
- ミニゲーム2つ（算数1・国語1）。難易度段階つき（3章）
- 出動（4問のセッション）→ ごほうび（はたらく車カード）→ しゃこ（図鑑）の循環
- 保護者向けの簡単な画面（進み具合・音のオン/オフ・難易度の固定・データ消去）
- 進み具合の localStorage 保存

### やらないこと（MVP）
- ひらがなの書き・なぞり、カタカナ、漢字、英語
- 算数: ひきざん、11以上、くり上がり（ひきざんは後から M6・M7 として追加。12章）
- ログイン、サーバー、ランキング、広告、課金、外部画像・外部音声ファイル、BGM
- 複数ユーザー（子ども）の切り替え（端末1台に1人分）
- Web 公開（**外部公開にあたるため、実施前に人間の承認が必要**。MVP の完了条件は「ローカルで遊べる状態」まで）

### 完了条件
受け入れ条件（12章）をすべて満たし、純粋関数のテストが通り、reviewer のレビューを経て main にマージされていること。

## 2. ストーリーと世界観

- 子どもは「しょうぼうしゃ」の運転手。しょうぼうしょ（消防署）にベルが鳴り、「しゅつどう！」で現場へ向かう。
- 現場では火事や困りごとが起きている。問題に正解するたびに、しょうぼうしゃが放水したり、仲間の車が助けに来たりして、現場が少しずつ片づく。
- 最後の問題で全部解決。お礼に、はたらく車のカードがもらえる。
- 現場は3種類を持ち回り（MVP）。問題の種類（算数/国語）とは独立で、出動のたびにランダムまたは順番。
  1. **かじ**（ビルの火事）: 正解ごとに放水で火が小さくなる。主役: しょうぼうしゃ・みずタンクしゃ。
  2. **たかいところ**（木の上のねこ）: 正解ごとにはしごが伸びる。主役: はしごしゃ・ちょうだいはしごしゃ。
  3. **みちのこまりごと**（土砂・がれきで道がふさがる）: 正解ごとにがれきが片づく。主役: ショベルカー・ダンプカー・ブルドーザー。きゅうきゅうしゃが最後に到着。
- 現場の演出は Canvas 描画（hataraku-drop の `src/render.js` の描画関数を流用、4章）。実在メーカーのロゴ・キャラクターは使わない。

## 3. 学習内容と難易度

### 3.1 算数: 「かずをかぞえよう」（MVP ミニゲーム1）

| レベル | 内容 | 選択肢の数 |
|---|---|---|
| M1 | かぞえる 1〜3 | 3 |
| M2 | かぞえる 1〜5 | 3 |
| M3 | かぞえる 1〜10 | 4 |
| M4 | たしざん 和が5以下（例 2+1） | 3 |
| M5 | たしざん 和が10以下（例 4+3） | 4 |

- **かぞえる問題**: 現場に N 個の「もの」（火・がれき・ねこ等、現場に合わせる）が並ぶ。子どもはものをタップして数えてもよい（タップするとその個数が音声で読まれ、印がつく。任意）。答えは下の「数字ボタン」から選ぶ。数字ボタンには数字（大きな数字）と、その個数分の点（ドット）を併記し、数字が読めなくても対応が分かるようにする。
- **たしざん問題**: 左に A 個、右に B 個の「もの」を並べ、真ん中に「たす」アイコン（＋）。答えを数字ボタンから選ぶ。式は読み上げる（「2 たす 1 は？」）。A,B ≥ 1、A+B は上限以下。
- 配置は規則的（5個ずつ段にする等）にして数えやすくする。ランダム散らばりは M3 のみ可。
- 数え方の読み上げ: いち、に、さん、し(よん)、ご、ろく、なな、はち、きゅう、じゅう。「し」ではなく「よん」を使う。

### 3.2 国語: 「ひらがなさがし」（MVP ミニゲーム2）

**形式**: はたらく車（またはものの絵）が1つ表示され、音声で「はしごしゃ。さいしょのもじは？」と読み上げる。下に並んだひらがなのボタンから、頭文字（は）をタップする。ボタンをタップするとその文字が読み上げられる（読みの練習）。

**選んだ理由（推奨案を採用）**: 乗り物の絵＋名前の頭文字は、好きなものを足がかりに文字と音を結びつけられ、字が読めない子でも「絵を見る・音を聞く」で参加できる。単独のひらがな読み上げ（「『は』を探そう」）は、Web Speech が1文字を不自然に読む端末があるため主形式にしない。代わりに「はしごの『は』」という単語つきの読み上げを使う。

| レベル | 使う文字 | 選択肢の数 | 紛らわしさ |
|---|---|---|---|
| K1 | 見た目も音も離れた文字（下表 A グループ） | 2 | 行が違う |
| K2 | A グループ＋Bグループ | 3 | 行が違う |
| K3 | 全 MVP 単語の頭文字 | 4 | 形が似た文字を1つ混ぜてよい（下表「まぎらわしい組」） |

**単語表（データとして実装。頭文字は清音・濁音・半濁音の1文字で、拗音「ゃゅょ」で始まる単語は使わない）**

| id | 表示（ひらがな） | 頭文字 | 絵 | グループ |
|---|---|---|---|---|
| hashigo | はしごしゃ | は | はしごしゃ | A |
| neko | ねこぐるま | ね | ねこぐるま | A |
| gomi | ごみしゅうしゅうしゃ | ご | ごみしゅうしゅうしゃ | A |
| mizu | みずタンクしゃ | み | みずタンクしゃ | A |
| dump | ダンプカー（表示は「だんぷかー」） | だ | ダンプカー | A |
| buru | ぶるどーざー | ぶ | ブルドーザー | B |
| hose | ほーす | ほ | ホース（小物。Canvas で簡単に描く） | B |
| hi | ひ | ひ | ほのお（小物。Canvas で簡単に描く） | B |

> 注: 実装者は上の 8 語のみをデータ化する。しょうぼうしゃ（しょ）・きゅうきゅうしゃ（きゅ）・ショベルカー（しょ）・フォークリフト（ふぉ）・ちょうだいはしごしゃ（ち、ただし「ちょ」と紛らわしい）は、頭文字が拗音・外来音で曖昧になるため **国語問題には出さない**。現場の演出・図鑑・ごほうびには登場する。**未決事項 U1** 参照。
> 文字の例語（選択肢タップ時の読み上げ用）: は→はしご、ね→ねこ、ご→ごみ、み→みず、だ→だんぷ、ぶ→ぶるどーざー、ほ→ほーす、ひ→ひ。
> 選択肢に混ぜる誤答用の文字は上の 8 文字から選ぶ（K1/K2 は各グループ内、K3 は全 8 文字）。

**まぎらわしい組**（K3 で誤答に混ぜてよい。同じ組は両方とも正解になりうる単語が同時に出ないように注意）: は–ほ、ね–ぬ、み–め、ご–こ、だ–た、ぶ–ぷ。

**音声の台本（`speech`）**
- 出題: 「{単語}。さいしょのもじは？」
- 選択肢タップ: 「{例語}の {文字}」（例: 「はしごの、は」。単独の1文字読みは不自然な端末があるため避ける）
- 正解: 「そう！ {文字}！ {単語}の {文字}」

### 3.3 レベルの進め方（自動＋保護者が固定可能）
- 算数と国語は**別々にレベルを持つ**。初期は M1 / K1。
- 昇級: 直近の出動（4問）で「1回目で正解」が 4/4 のとき、次回から1つ上のレベル。
- 降級: 直近の出動で1回目正解が 0〜1/4 のとき、次回は1つ下のレベル（下限あり）。
- それ以外は同レベル継続。
- 保護者画面で「レベルを固定」できる（固定中は昇降級しない）。
- 1回の出動に混ぜる問題の種類（MVP）: 1回の出動 = 算数4問 **または** 国語4問。どちらにするかは、出動前の「どっちでしゅつどう？」で子どもが選ぶ（アイコンは「かず」＝数字と点、「もじ」＝あ）。連続で同じ側を選んでもよい。選ばせるのは、飽きの防止と、子ども自身の選択による没入のため。

### 3.4 ヒントと失敗時の流れ（全ゲーム共通）
1. 1回目の誤答: そのボタンを軽く揺らして薄くする（無効化）。声: 「おしい！もういちど」。
2. 2回目の誤答: 正解のボタンをゆっくり拡大縮小で光らせる。声: 「こっちかな？」。（算数では、数えるものを1つずつ光らせて数え聞かせる）
3. 残り選択肢が正解だけになったら、タップで正解扱い。
- 正解扱いは1回目・2回目以降で区別して記録する（進み具合・昇降級の判定用）。ただし画面上で「間違い」は強調しない（点数やバツ印は出さない）。
- 3回以上間違えても、ごほうび（カード）の内容は変わらない。

## 4. 画面と流れ

画面はすべて1ファイルの SPA 的構成（`index.html` 内で画面 div を切り替える）。

```
[タイトル] → [出動えらび（かず/もじ）] → [出動（4問）] → [ごほうび（カード）] → [しゃこ] ⇄ [タイトル]
                         ↑                                                 ↓
                         └────────────── もういちど ←──────────────────────┘
[タイトル] → [おうちのひと（保護者）]
```

1. **タイトル**: ロゴ（はたらくまなび）、しょうぼうしゃが走るアニメ。大きなボタン3つ: 「しゅつどう」（消防車アイコン）、「しゃこ」（ガレージアイコン）、小さく右上に歯車（保護者へ。長押し2秒で開く＝誤タップ防止）。音のオン/オフ（スピーカーアイコン）。
2. **出動えらび**: 大ボタン2つ「かず」「もじ」。タップで出動開始。
3. **出動（問題画面）**:
   - 上: 進み具合（4つの小さな消防車/ランプ。クリアで点灯）。
   - 中央: 現場（Canvas）。問題の絵（数える対象、車の絵など）。
   - 下: 答えボタン（3〜4個、横並び。縦画面でも横並びで折り返さない大きさ）。
   - 左下: 「もういちどきく」（スピーカーアイコン）。問題の読み上げを再生。
   - 正解時: 放水/はしご/がれき撤去のアニメ→次の問題へ（約2秒）。
   - 4問目の正解 → 現場クリア演出（約3秒）→ ごほうび。
   - 途中でやめるアイコン（×）は小さく端に置き、長押し2秒で「タイトルへ」。途中経過は保存しない（出動はやり直し）。
4. **ごほうび**: カードがめくれるアニメ（効果音つき）。「○○をゲット！」と読み上げ。車の絵＋名前（ひらがな）。すでに持っている車ならカードに★が1つ増える（★は最大3）。ボタン: 「しゃこへ」「もういちど」。
5. **しゃこ（車庫）**: 11種の車を並べたガレージ棚。未入手はシルエット（黒塗り）＋「？」。入手済みはカラー絵＋★の数。タップすると車が走るアニメ＋名前の読み上げ（学習の復習にもなる）。
6. **おうちのひと（保護者）**: 10章。

## 5. 音声・演出

### 音声の方針
- 読み上げ: Web Speech API（`speechSynthesis`、`lang='ja-JP'`、`rate` 約0.85、日本語音声が見つかればそれを選ぶ）。
- 効果音: Web Audio の発振器で合成（外部ファイルなし）。種類: タップ、正解（上昇音）、おしい（やさしい低め2音）、放水（ノイズ＋フィルタ）、サイレン（上下に揺れる音）、カードめくり、ファンファーレ。
- **音声が出ない端末への対応（重要）**:
  - `speechSynthesis` が無い、または `getVoices()` に ja が無い、または読み上げ開始イベントが来ない場合は「声なしモード」に自動で切り替える。
  - 声なしモードでも、問題の内容は **絵とアニメだけで伝わる** ようにする: 国語は、声なしでは「どの文字か」を伝えられないため、車の絵が跳ねる→1回目の誤答で（3.4 の2回目を待たず）正解ボタンを光らせる、と早める。声なしモードでは国語の学習効果が下がることを保護者画面に案内する。
  - 算数は、数えるものが1つずつ跳ねてカウントアップし（音は「ぽん」の音程が上がる効果音）、数字ボタンに対応するドットがあるため、声なしでも解ける。
  - 声が使えない場合、画面に小さなスピーカー×アイコンを出して、保護者が気付けるようにする（子どもには影響しない）。
- iOS Safari は、最初のユーザー操作の中で `speechSynthesis.speak` を呼ばないと無音になることがあり、日本語音声が未導入の端末もある。**最初のタップ（タイトルの「しゅつどう」など）でダミーの読み上げ（空文字または短い無音）と AudioContext の resume を行う**。
- 自動再生制限のため、最初の操作の前に音を鳴らさない。
- 読み上げと効果音が重ならないよう、読み上げ前に `speechSynthesis.cancel()`、効果音は短く。

### 演出の方針
- 動きは大きく・ゆっくり・やさしく。点滅の速い演出（光過敏への配慮）、画面全体の急な赤フラッシュは使わない。
- 正解のたびに小さなごほうび（星のきらめき、車がクラクション）。間違えたときは叱る演出なし。
- 現場 3 種は Canvas で描く（建物・炎・水しぶき・はしご・がれき）。炎は簡単な図形＋ゆらぎで描く。
- `prefers-reduced-motion` のときは揺れ・拡大縮小を弱める。

## 6. ごほうびの仕組み（「飽きずに」の中心）

- 出動を終える（4問に正解する）と、**はたらく車のカード**を1枚もらう。間違えた数に関係なくもらえる。
- カードは11種（hataraku-drop と同じ）: ねこぐるま・フォークリフト・ごみしゅうしゅうしゃ・ショベルカー・ブルドーザー・ダンプカー・きゅうきゅうしゃ・しょうぼうしゃ・みずタンクしゃ・はしごしゃ・ちょうだいはしごしゃ。
- **もらえる車の決め方**:
  1. 1回目の出動は必ず「しょうぼうしゃ」（導入の達成感）。
  2. その後は、未入手の車の中から、出動した現場に関係する車を優先して抽選（かじ→みずタンクしゃ/はしごしゃ系、みち→ショベル系/きゅうきゅうしゃ 等）。関係する未入手が無ければ未入手全体から抽選。
  3. 全種入手後は、★（最大3）が少ない車から抽選して★を増やす。
  4. 全車が★3になったら、カードのかわりに「ごほうびステッカー」（色違い）をもらう。MVP ではここで止めてよい（未決事項 U5）。
- 総コレクション: 11種 × ★3 = 33ステップ。1日1〜2回の出動なら約3週間。「あと1回でちょうだいはしごしゃ」のような期待をつくる。
- 「しゃこ」で未入手が黒シルエットで見えることが、次の出動の動機になる。
- 3日連続など日をまたぐ仕組み（スタンプ帳）は将来案。MVP では出動のたびにタイトルの消防署の窓にあかりがつく程度（累計出動数 10 回ごとに窓が増える、は将来案でも可）。

## 7. 画面レイアウト・操作

- 対応: スマホ・タブレットの縦/横、PC。画面サイズに合わせて Canvas を拡縮（`devicePixelRatio` 考慮、`fit` 方式。論理サイズ 960×600 の横長を基準に、縦画面では現場を上、ボタンを下に再配置）。
- タップ領域は短辺 **最低 72px 相当**（できれば 96px）、ボタン間隔 16px 以上。誤タップ防止のため、ボタンの当たり判定は見た目より大きくする。
- マルチタッチ・ダブルタップ拡大・長押しメニュー・テキスト選択を無効化（`touch-action: manipulation`、`user-select: none`、`-webkit-touch-callout: none`）。
- キーボード操作は MVP 外（PC はマウスで操作）。
- ブラウザの戻る/リロードで進み具合が消えないこと（localStorage）。

## 8. 問題生成（純粋関数・テスト対象）

ファイル: `src/problems.js`（DOM・音・時間に依存しない。ブラウザでは `window.Manabi.problems`、Node では `module.exports` で参照できる classic script 形式。`scripts/test.sh` から Node で実行）。

乱数は外から渡す（`rng` は `() => 0以上1未満` の関数。省略時は `Math.random`）。テストでは固定シードの乱数を渡す。

```
generateCounting(level, rng)  // level: 'M1'|'M2'|'M3'
  -> { kind:'count', level, n, choices:[number...], answer:n }
generateAddition(level, rng)  // level: 'M4'|'M5'
  -> { kind:'add', level, a, b, choices:[number...], answer:a+b }
generateLetter(level, rng, prevWordId)  // level: 'K1'|'K2'|'K3'
  -> { kind:'letter', level, wordId, word, choices:[kana...], answer:kana }
generateSession(game, level, rng)  // game: 'math'|'letter'
  -> 問題4つの配列（同じ問題が連続しない。letter は同じ wordId を重複させない）
```

**満たすべき性質（テストで検証）**
1. `choices` に `answer` がちょうど1回含まれる。
2. `choices` に重複がない。長さはレベルの選択肢数（3.1・3.2 の表）と一致。
3. 数値の選択肢はレベルの範囲内（M1: 1〜3、M2: 1〜5、M3: 1〜10、M4/M5: 1〜上限）。0 や負数は含まない。
4. 数値の誤答は「正解の±1〜2」を優先し、範囲に収まらない分は範囲内の別の数で補う。これにより、選択肢が3つ以上を確保できること（例: 正解1・範囲1〜3 → {1,2,3}）。
5. たしざん: 1 ≤ a, 1 ≤ b, a+b ≤ 上限（M4: 5、M5: 10）。M4 には a+b が 5 以下のものすべてが出うる。M5 は a+b ≥ 6 を少なくとも半分含める。
6. 国語: `answer` は単語表の頭文字と一致。誤答は同レベルで許される文字から選び、`answer` と重複しない。K3 の「まぎらわしい組」混入時も、正解以外の選択肢の文字が、現問題の単語の頭文字と一致しない。
7. `generateSession` は4問を返し、全問が `choices` 性質を満たす。同じ問題（kind・値が同一）が連続しない。
8. 同じシードなら同じ結果（決定的）。
9. レベル昇降級の関数 `nextLevel(game, current, firstTryCorrectCount, locked)` も純粋関数にしてテスト（3.3 の規則。上限 M5 / K3、下限 M1 / K1）。
10. ごほうび抽選 `pickReward(owned, scene, rng)` も純粋関数にしてテスト（6章の規則。1回目は必ず しょうぼうしゃ）。

## 11. 技術方針

hataraku-drop（`/Users/ysuzuki/ai-company/projects/hataraku-drop`）と同じ前提。

- 素の HTML / CSS / JS。ビルドなし。**classic script**（`type="module"` を使わない。`<script src>` を順に読む）。**`file://` で `index.html` を開いて動く**こと。
- 外部画像・外部音声・外部フォント・CDN なし。通信ゼロ。
- 乗り物の絵: hataraku-drop の `src/render.js` の描画関数（`drawVehicle(ctx, stage, x, y, angle, pop, off)`、`drawCentered`、`drawPreview` など）を **コピーして流用**（11種の絵は段階 1〜11 に対応）。コピー元とコピーの対応表を `docs/` か `src/` 冒頭コメントに残す。現場の絵（建物・炎・がれき等）は新規に Canvas で描く。
- 推奨ファイル構成（設計・実装で変更可）:
  ```
  index.html
  src/vehicles.js   // render.js から流用した描画 + 車id・名前・段階の対応
  src/problems.js   // 8章の純粋関数
  src/rewards.js    // pickReward, nextLevel 等の純粋関数
  src/storage.js    // localStorage の読み書き・初期化
  src/audio.js      // Web Audio の効果音
  src/speech.js     // Web Speech、声なしモード判定
  src/scenes.js     // 現場の描画
  src/ui.js         // 画面遷移・イベント
  src/main.js
  css/style.css
  scripts/test.sh   // Node で純粋関数のテスト
  ```
- 名前空間 `window.Manabi` に各モジュールを登録し、Node ではテスト用に `module.exports`（`typeof module !== 'undefined'` で判定）。
- 実在メーカーのロゴ・既存キャラクターは使わない。

## 12. 受け入れ条件（テスト可能な形）

1. `index.html` を `file://` で開くとタイトルが表示され、コンソールにエラーが出ない。外部への通信が発生しない。
2. 「しゅつどう」→「かず」/「もじ」を選ぶと、4問の出動が始まり、全問正解して進むと「ごほうび」画面に着く。
3. 誤答しても画面が止まらない（ゲームオーバーにならない）。1回目の誤答でそのボタンが無効化され、2回目の誤答で正解が光り、最終的に必ず正解して進める。
4. 算数の全レベル（M1〜M5）、国語の全レベル（K1〜K3）が、保護者画面でレベル固定して遊べる。
5. 問題生成の関数が 8章の性質を満たす（`scripts/test.sh` が Node で通る。固定シードで各レベル最低 1000 問を生成して全性質を確認）。
6. 昇降級（`nextLevel`）、ごほうび抽選（`pickReward`）のテストが通る。1回目の出動で必ず「しょうぼうしゃ」を得る。
7. 「しゃこ」で入手済み/未入手（シルエット）が正しく表示され、リロード後も保持される。
8. 音声: 日本語音声が使える環境では問題が読み上げられる。使えない環境（`speechSynthesis` を無効化して確認）でも、エラーなく最後まで進行でき、効果音とアニメで解ける。
9. 音のオン/オフが保護者画面とタイトルで切り替えられ、リロード後も保持。オフ時は効果音も読み上げも出ない。
10. スマホ縦（幅 360px）、スマホ横、タブレット、PC 幅の各サイズで、現場・答えボタンが画面内に収まり、答えボタンの当たり判定が短辺 72px 以上ある。
11. 画面上の文字は子ども向け部分でひらがなのみ（漢字なし。外来語はひらがな表記）。
12. 外部画像・実在ロゴ・既存キャラクターを含まない。localStorage が使えなくてもクラッシュしない。

## 12. 追加段階 M6・M7 ひきざん（2026-10-24 追加依頼）

依頼: 「数の問題のステップアップで引き算も」。MVP の「やらないこと」（2章）にあった ひきざん を、M5 の次の段階として足す。11以上・くり下がりは引き続きやらない。

| レベル | 内容 | 選択肢 |
|---|---|---|
| M6 | ひきざん 5以下から引く（例 5−2） | 3 |
| M7 | ひきざん 10以下から引く（例 8−3）。a≥6 を半分以上 | 4 |

### 契約（実装の分担の境目）
- **問題**: `generateSubtraction(level, rng)` → `{ kind:'sub', level, a, b, choices:[数...], answer: a-b }`。`2 ≤ a ≤ max`、`1 ≤ b`、`a-b ≥ 1`（答え 0 は出さない）。選択肢は既存の `numberChoices(answer, max(a, choices), choices, rng)`（1〜a、0なし。a は「引き忘れ」の誤答。a より大きい数は答えになりえないので出さない）。`sameProblem` は a・b で比べる。`generateSession('math', 'M6'|'M7')` に対応。`LEVELS.math` と storage の `MATH_LV` は M1〜M7。
- **現場**: a 個のものを並べ、出題から約1秒後に、うしろの b 個が「いなくなる」演出（火は水で消える／ねこは助け出される／いわはどかされる。どれも薄くなって×印）。いなくなった b 個は薄く残し、数えないものと分かるようにする。**`stage.items` は残る a−b 個だけ**（タップして数える・ヒントの数え聞かせ `countAloud` は残りだけを数える）。いなくなる b 個は別の配列で持つ。
- **読み上げ**: 出題「{NUMK[a]}ひく{NUMK[b]}は、いくつ？」（数の読み。スペースなし）。正解「そう！{NUMK[answer]}！」。2回の誤答で正解が光り、残りを1つずつ数え聞かせる（たし算と同じ流れ）。
- **確認パネル**: M6・M7 のボタンを足す。`#debug:play-math-M6-kaji-0` で出せる。
- **進級**: M5 で 4/4 なら M6 へ（保護者画面で固定できる）。
- 1〜11章の M5 までの記述（選択肢の範囲・上限など）は、M6・M7 についてはこの章を正とする。
