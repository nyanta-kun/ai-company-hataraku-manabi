### 2.4 大きさ

- ふつうの日（2〜3 ゲーム・5 回くらい）: JSON で約 150〜250 字。
- 多い日（6 ゲームすべて、書いた字 30 字、新しい乗り物 3 つ）: 約 400 字。
- 35 日 × 4 人をすべて多い日で埋めても約 56,000 字（UTF-16 で約 110 KB）。localStorage の上限の目安（5 MB 前後）から遠い。保存のたびの `JSON.stringify` も数ミリ秒以下。
- 件数の上限（6.2）で、壊れたデータや時計の狂いでも 40 日分を超えない。

## 3. 日付の決め方

- **鍵は端末の日付**（`todayStr()` と同じ `YYYY-MM-DD`）。今の `lastPlayed`・`cleared`・`promoted` と同じなので、「関門を通った日」と日ごとの行が必ず一致する。
- **日付が変わる時刻は 0 時**。朝 4 時などで切ると、`cleared` の日付とずれて「できるようになったこと」が別の日に出る。夜中に遊ぶ年齢ではないので 0 時で困らない。
- **日付をまたぐ出動**: 出動の回数・問題・ごほうび・時間は**終わった日**に付ける（`finishSession` が `todayStr()` を呼ぶ時点。`lastPlayed` と同じ）。かく の字は書き終えたその時の日付に付ける（今の `stats.trace.chars` と同じ時点）。23:59 に始めて 0:01 に終えた かく は、字が前の日・出動が次の日に分かれうるが、まれで実害が無いので受け入れる。
- **時差・時計の狂い**: 端末の日付をそのまま使う。記録するとき（6.1）に、今日より 2 日以上先の鍵は消す（時計を未来に合わせてから直したとき、その日の記録がずっと「いちばん新しい日」として残るのを防ぐ）。1 日先までは残す（西へ旅行して時差で日付が戻った場合）。
- **週**: 月曜はじまり（企画 U1）。曜日は鍵の文字列を `Date.UTC` で数に直して求める（端末の時差・夏時間の影響を受けない）。

## 6. 保持・補正・壊れたデータ

### 6.1 記録するときの剪定（今日が分かる場面）

`recordSession`・`recordChar`・`addTime` は、書き込んだ後に `prune(days, today)` を通す:
- `today` から 34 日より前（`addDays(today, -34)` より小さい鍵）を消す → 今日を含めて 35 日。
- `today` の 2 日以上先の鍵を消す（3 章）。

### 6.2 読み込みの補正（`normalizeProfile` の中。今日を使わない）

`normalizeProfile`（`src/storage.js:82-112`）に `d.days = DL.normalizeDays(raw.days)` を足す。`defaultProgress()`（`src/storage.js:24-44`）に `days: {}` を足す。

`normalizeDays(raw)` の規則（壊れた値は捨てる。全体を捨てずに、使える日・項目だけ残す）:
- 表でなければ `{}`。鍵が `YYYY-MM-DD` の形で、実在する日付（`2026-02-30` は捨てる）だけ。
- 鍵を新しい順に並べ、**40 件まで**（今日が分からなくても大きさを縛る）。
- 回数は 0 以上の整数（今の `num()` と同じ。`src/storage.js:45`）に直し、上限で止める: `sessions` 999、`questions` 9,999、`firstTry` は `questions` まで、`chars` 9,999、`cards` 999、`sec` 86,400。
- 知らないゲームの鍵は捨てる。中身がすべて 0 のゲームは鍵ごと消す。
- `up[g]` は `D.LEVELS[g]` にあるレベルだけ（`trace`・`solo` には持たない）。
- `wrote` は書ける字（`src/strokes.js` の `SETS` の全部）だけ、重なりを除いて 130 字まで。`newChars`・`newSolo` は `wrote` にある字だけ。
- `license` は `hira`・`kata`・`k1`・`k2` だけ、重なりなし。`newCars` は乗り物の id（`D.ALL_VEHICLES`）だけ、重なりなし、47 件まで。
- `last` は 6 つのゲームの名前のどれか、でなければ `''`。
- 何も残らない日は消す。
- 入力は書き換えない。`normalizeDays(normalizeDays(x))` は `normalizeDays(x)` と同じ。

### 6.3 既存のデータ

- 日ごとの記録が無い今のデータ・v1 からの移行（`migrateV1`。`src/storage.js:174-183`）は `days: {}` になる。今までの画面・数は変わらない。
- 今までの合計（`stats`）から日ごとの記録は作らない（何日に遊んだかが分からないため）。保護者画面の最初の週は、出した日からの分だけ。
- 今のテストへの影響: `assert.deepEqual(S.normalizeProfile(null), S.defaultProgress())`（`tests/storage.test.js:21`）・`tests/english.test.js:150` は、両方に `days: {}` が入るので通る。プロフィール全体を決め打ちの形と比べている試験があれば `days: {}` を足す（DL-1 で `bash scripts/test.sh` を回して直す）。

## 10. R4（クラウド）: 日ごとの記録も保存する（ユーザーの回答 2026-10-28）

ユーザーの回答で「クラウドにも保存する」に決まった（企画 6 章）。プロフィールの文書の項目数（`firestore.rules:92` の `size() == 15`）と式の上限（1 人の文書で約 750〜800 式・余裕 約 2 割。`docs/r4-firebase-setup.md` 5.2）に触れないよう、**プロフィールとは別の文書**にする。R4 の Firebase はまだ作っていない（`docs/r4-firebase-setup.md:3`）ので、ルールと試験はエミュレーターだけで先に作れ、承認は要らない。実際に送るのは R4 の `cloud.js`（R4-a・R4-b。承認の後）。

### 10.1 文書の分け方の比較

前提: **ルールには繰り返しが無い**。中身の鍵が決まっていない表（例: 日付 → 1 日の表）は、1 つずつの中身を検査できない（今の `trace.done` のように「値を全部つないで 1 つの正規表現」に落とせるのは、値が数や日付などの 1 つの文字列のときだけ）。1 日の中身は入れ子なので、**1 文書に 1 日**にして、決まった項目を 1 つずつ書き出して検査する。

数の見込みは「1 家族・子ども 2 人・端末 2 台・1 日に出動 20 回・保護者画面を 2 回開く」。

| 案 | 文書 | 書き込み／日 | 読み取り／日 | 式の数（1 書き込み） | 35 日より古いものの消し方 | 判断 |
|---|---|---|---|---|---|---|
| **A. 1 日・1 端末で 1 文書（推奨）** `profiles/{pid}/days/{YYYY-MM-DD}_{端末の番号}` | 1 人あたり最大 35 × 端末の数 | 出動ごとに 1（20）。ルールが親を見る読み取りが 1 回ずつ（20） | 保護者画面を開いたとき、その子の 35 日 × 端末の数まで（2 回 × 最大 70 = 140）。古い文書を探す問い合わせ 1 日 1 回（見つかった数、ふだん 0〜2。何も無くても 1 回分）。子を消すときの一覧（その子の文書の数、まれ）。起動では読まない | 約 40（10.4） | 同期のとき、`date < 今日 − 34` の文書を問い合わせて消す（1 日 1〜2 削除） | 採用。1 台が書くのは自分の文書だけなので、2 台が同じ文書を取り合わない（トランザクション不要）。2 台の回数を足しても二重にならない |
| B. 1 日 1 文書（端末を分けない） `days/{YYYY-MM-DD}` | 最大 35 | 出動ごとに 1。2 台が同じ日に書くので、読んでから書くトランザクション（読み取り 1 ＋ 書き込み 1） | A の半分 | 約 40 | A と同じ | 2 台で同じ日に遊ぶと、「大きい方」なら少なく数え（iPad 3 回・iPhone 2 回 → 3 回）、「足し算」なら同じ差分を送り直したときに二重に数える。差分を正しく送るには「どこまで送ったか」を端末ごとに覚える必要があり、A より作りが大きい。不採用 |

| D. 1 か月 1 文書 | 最大 2 | 同上 | 最少 | 31 日分で 1,000 を超える | 同上 | ルールが上限に収まらない。不採用 |

### 10.2 端末の番号

- A では、文書の名前に**端末の番号**を使う。`device.deviceId`（`'d_' + 小文字の英数字 8 字`。乱数で作る。`newId`（`src/storage.js:52-55`）と同じ作り方）を端末共通の `device` に足し、`normalize` で補う（無ければ作る）。

- この番号は、日ごとの記録の文書の名前と中身の `dev` にだけ使う。プロフィール・親の文書には入れない。
- これまでの説明「端末の識別番号は集めない」（`docs/r4-data-and-privacy.md:43`）の言い方を直す（10.7）。

```
    // families/{uid}/profiles/{pid}/days/{did}   did = 'YYYY-MM-DD_' + 端末の番号。1 日・1 端末で 1 文書
    // 乗り物の id（src/storage.js の CAR_IDS と同じ。isCards と同じ並び。ずれたら tests-rules が失敗する）
    function dayCarPattern() {
      return '(nekoguruma|forklift|gomi|shovel|bulldozer|dump|kyukyu|shoubousha|mizutank|hashigo|chodai|rescuework|rescuechem|rescuecmd|rescueheli|patrol|bus|taxi|postcar|truck|motorbike|crane|roller|train|shinkansen|steam|tram|monorail|freight|cablecar|hayabusa|komachi|kagayaki|doctoryellow|linear|airplane|heli|rocket|balloon|airship|propplane|ship|fishboat|yacht|tugboat|fireboat|cargoship)';
    }
    // 書ける字だけの文字列（空も通る。130 字まで）。重なりと「newChars・newSolo は wrote の中」は端末の normalizeDays が守る
    function isTraceStr(s) {
      return s is string && s.size() <= 130 && s.matches('^' + traceCharPattern() + '*$');
    }
    // 回数 18 個: かず・もじ・とけい・えいご の（回数 3 けた, 問題 4 けた, 1 回目で正解 4 けた）、かく・ひとりで の（回数 3 けた, 字 4 けた）、ごほうび 3 けた、秒 5 けた
    function isDayCounts(n) {
      return n is list && n.size() == 18
        && n.join(',').matches('^([0-9]{1,3},[0-9]{1,4},[0-9]{1,4},){4}[0-9]{1,3},[0-9]{1,4},[0-9]{1,3},[0-9]{1,4},[0-9]{1,3},[0-9]{1,5}$');
    }
    function isDay(d, did) {
      return d is map
        && d.size() == 11
        && d.v == 1
        && d.date is string && d.date.matches('^[0-9]{4}-[0-9]{2}-[0-9]{2}$')
        && d.dev is string && d.dev.matches('^d_[0-9a-z]{8}$')
        && did == d.date + '_' + d.dev
        && isDayCounts(d.n)
        && d.up.matches('^(M[0-9]{1,2})?,(K[0-9]{1,2})?,(T[0-9]{1,2})?,(E[0-9]{1,2})?$')
        && isTraceStr(d.wrote) && isTraceStr(d.newChars) && isTraceStr(d.newSolo)
        && d.license.matches('^((hira|kata|k1|k2)(,(hira|kata|k1|k2)){0,3})?$')
        && d.newCars.size() <= 700
        && d.newCars.matches('^(' + dayCarPattern() + '(,' + dayCarPattern() + '){0,46})?$')
        && d.last.matches('^(math|letter|clock|english|trace|solo)?$');
    }
```

- `date`・`dev` は先に文字列と形を確かめ、そのうえで `did` が `date + '_' + dev` と一致することを見る（数などが入っていても `+` の型の誤りに頼らず、はっきり拒否する）。

### 10.5 端末とクラウドのまとめ方

- **自分の端末の文書**（`dev` が自分）: 端末の `days` が正。クラウドには上書きで書く（`set`。読まずに書く）。同じ文書を書くのは自分だけなので取り合いが無い（同じ端末の 2 つのタブは今と同じく後に書いた方が残る。`docs/design-elementary.md` 2.3）。
- **ほかの端末の文書**: 読んで日ごとに**足し合わせ**、`daysOther`（プロフィールの中。端末の中だけ）に**丸ごと置き換えて**入れる（前の値と足さない。何度読んでも同じ結果）。
- **表示**: 保護者画面も子ども向けも `sumDays(days, daysOther)` を使う。

| 項目 | 足し合わせの規則 |
|---|---|
| 回数（出動・問題・1 回目で正解・字・ごほうび・秒） | 足す（端末ごとに別の文書なので二重にならない）。足した後で 6.2 の上限で止める |
| `up` | ゲームごとに高い方 |
| `wrote`・`newChars`・`newSolo`・`license`・`newCars` | 和集合（重なりを除く。並びは自分の端末の分が先、続いて端末の番号の順）。2 台でそれぞれ「初めて」書いた字は 1 つになる |
| `last` | 自分の端末の値。無ければ、ほかの端末のうち端末の番号の並びで先の値（決定的にするため） |

- 例: iPad（自分）で かず 3 回、iPhone で かず 2 回・かく 1 回の日 → 保護者画面は かず 5 回・かく 1 回。子ども向けは かず と かく にスタンプ、王冠は かず。
- **送るとき**: 出動を終えたとき・字を書いたとき・時間を足したときに、その日を「送る日」（`device.daysDirty`。日付の一覧、40 件まで。端末の中だけ）に入れる。`cloud.js` は 5 秒ためてから、送る日の文書を書き、成功したら一覧から消す。通信できないときは一覧が残り、次に送れるときに送る。35 日より古い日は送らずに一覧から消す。
- **読むとき**: **保護者画面の「まいにちの きろく」を開いたとき**と、ほかの子に切り替えたときに、その子の `days` を `where('date', '>=', 今日 − 34)` で一覧し、自分の `dev` 以外を `daysOther` にする。起動のたびには読まない（読み取りを減らすため）。子ども向けの画面は、手元の `daysOther`（前に読んだもの）を使う。読めないときは手元の値のまま出し、保護者画面に「ほかの たんまつの ぶんは まだ よみこめて いません」と出す。
- **消すとき**: 読む前に `where('date', '<', 今日 − 34)` の文書（どの端末のものでも）を消す。1 日に 1 回まで（`device.daysPrunedOn` に日付）。
- **プロフィールを消すとき・`ids` から外すとき**: その子の `days` を一覧して全部消す（Firestore はプロフィールの文書を消しても下の文書を消さない）。途中で通信が切れたら、次の同期で `ids` に無い子の `days` も消す（今の「`ids` に無い子の文書は消す」と同じ。`docs/r4-firebase-setup.md` 4.2）。
- **アカウントを消すとき**: 各プロフィールの `days` → プロフィール → 親 → 利用者の順に消す（`docs/r4-data-and-privacy.md` (d) の手順 3 に足す）。
- 「保存する」を選ばなかった子の `days` は送らない（プロフィールと同じ）。
- 初めてログインしたとき: 端末の `days` の 35 日分を全部「送る日」に入れる（この端末の分として送られる）。

## 12. テスト観点

1. **日付の境目**（`tests/daylog.test.js`）
