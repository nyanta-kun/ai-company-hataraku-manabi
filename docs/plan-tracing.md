## 1. 目的・対象・範囲

### 目的
- 読みだけだった「もじ」に、**書く入口**を足す。薄く出した字を指でなぞり、**字の形と書き順**を体で覚える。
- 小1・小2の子は、教材で読んだ漢字（K8・K9）を、なぞって書ける。

### 対象
- 主: 4歳〜小2。ひらがなは未就学（S0）から。漢字は読みで出した字（S1 の K8、S2 の K9）だけ。
- 端末: iPad（Safari）が主、iPhone（Safari）でも使う（plan-elementary.md 9章 U16）。指でも Apple Pencil でも書ける。

### 守ること（plan.md 1章・plan-elementary.md 1章をなぞりにあてはめる）

| 原則 | なぞりでの形 |
|---|---|
| 失敗状態なし | 点数・減点・時間切れはない。**線から大きく外れたら、その画だけやり直し**（字の最初からではない）。何度やり直しても字は終わり、出動は必ず最後まで進む（5章の「行き詰まらない工夫」） |
| 1回は短い | 1回の出動は **4字**（ランプ4つは今のまま。`index.html:57`）。ひらがなで約2〜3分 |
| 字が読めなくても遊べる | 始める位置は番号の丸と矢印、進み具合は線の色で見せる。声は補助 |
| 声が出なくても進める | 番号・矢印・光る始点・アニメーションのヒントだけで完結する |
| 子ども向けの文字（S0 はひらがなのみ） | 画面の文言はひらがな（「かく」「おてほん」）。なぞる字そのものは教材なので、S1 以降は漢字が出る（K8 と同じ扱い） |
| 通信ゼロ・個人情報なし | 指の線は**保存しない**（端末にも残さない）。保存するのは「どの字を何回書いたか」の数だけ（4.4） |

### やること
1. 出動えらびに5つめの「かく」を足す（2章）。
2. ひらがな46字 → カタカナ46字 → 小1の漢字（K8 の20字）→ 小2の漢字（K9 の字）を、なぞって書く。
3. 画ごとの判定（許容幅・始点から終点まで・向き）と、やり直し・ヒント（3章）。
4. 保護者画面に「かいた じ」の数と、線の幅の設定。

### やらないこと
- 手書きの認識（書き取り、自由に書いた字の判定）、厳密な筆順判定（はね・とめ・はらいの判定）。ユーザーの決定どおり。
- 点数・評価・お手本との「似ている度」の表示。
- 指の線（筆跡）の保存・共有・印刷。
- 濁点・半濁点・小さい字（が・ぱ・ゃ）は今回は入れない（将来案。7章）。

### 完了条件（全体）
5章の段階ごとの完了条件を満たし、純粋関数のテストが通り、reviewer のレビューを経て PR 経由で main に入っていること。iPad と iPhone の実機で、指と Apple Pencil（iPad のみ）で書き終えられることを確かめてあること。

## 2. どのゲーム・レベルとして入れるか

### 2.1 案の比較

| 案 | 内容 | 良い点 | 難点 |
|---|---|---|---|
| **A. 5つめのゲーム「かく」（推奨）** | 出動えらびに「かく」（えんぴつの絵）を足す。進み具合はゲームのレベルではなく「書いた字の数」で持つ | もじ（K1〜K9）の出題・昇降級・関門・テストに一切触れない。字が読めない子も絵のボタン1つで始められる。「よむ」と「かく」を別に進められる | 出動えらびのボタンが5つになり、並びを直す（iPhone 縦は 2×2 の下に横長の1つ。design-tracing.md 4.1）。保存・保護者画面に「かく」の欄を足す |
| B. もじ の中で「よむ／かく」を選ぶ | もじ を押すと2択の画面を出す | 出動えらびは今のまま | タップが1回増える。もじ のレベル（`levels.letter` は1つ）と、なぞりの進み具合が同じボタンの下で別々に動くので、保護者画面で分かりにくい |
| C. もじ の出動に混ぜる（読んだ字を1つなぞる） | K1〜K6 の正解のあとに、その字をなぞる | 読みと書きがつながる | 1問が長くなり「1回4問・2〜3分」が崩れる。`firstTry`（1回目正解の数）で決まる昇降級・関門（`src/ladder.js:34-50`）の意味が変わり、既存のテストと受け入れ条件に響く |

**推奨: A**。理由: 既存のもじ（読み）の仕組みを変えずに足せて、壊す心配が最も小さい。進み方を「書いた字の数」で持てるので、点数を使わない（失敗状態なし）。C の良さ（読みとのつながり）は、なぞる字に例語と絵を付けて取り込む（3.2）。

### 2.2 関門に入れるか
**入れない**（えいごと同じ扱い。plan-elementary.md 9章 U2）。理由:
- 関門は「最後のレベルを 1回目正解 4/4」で決まる（`src/ladder.js:41-48`）。なぞりには正解・不正解がなく、この形に合わない。
- 書く力は手の発達の差が大きい。関門にすると、読み・計算が進んでいる子が書きで止まる。
- U2 で決まった関門の条件を変えずに済む。

### 2.3 階段（S0・S1・S2）への載せ方

| ステージ | なぞる字（推奨） | 数 | 備考 |
|---|---|---|---|
| S0 みならい | ひらがな46字 → カタカナ46字（ひらがなを全部1回書いたら、カタカナが出始める） | 92字 | 読みも S0 で ひらがな・カタカナ（K1〜K6）なので揃える |
| S1 しょうぼうし | 小1の漢字（K8 の20字。`src/data.js:217-238`） | 20字 | 読みで出した字だけ（U4「教材で出した漢字だけ」と同じ考え） |
| S2 たいいん | 小2の漢字（K9 の字。R3 で決まる。候補18字は design-elementary.md 3.8） | 約20字 | 画数の多い字（電 13画・線 15画など）は外す案がある（T5） |

- ステージの札（出動えらびの上の札）で選んでいるステージの字が出る。S1 の子が S0 の札を選べば、ひらがな・カタカナを書ける（復習）。なぞりには「レベル」が無いので、どのステージで書いても「書いた字の数」が増えるだけで、ほかのゲームの進み具合は変わらない。
- 保護者画面で「なぞる じ」を選べる: 「じどう（ステージどおり）」「ひらがな」「カタカナ」「1ねんの かんじ」「2ねんの かんじ」（解放済みのステージの字だけ）。小1 の子にひらがなを書かせたい家庭のため。
- **カタカナを S0 に置くか S1 に置くか**は確認する（T3）。学校では、カタカナを書くのは小1の内容。一方、このアプリでは読み（K4〜K6）が S0 にある。推奨は S0（ひらがなの後）。

### 2.4 1回の問題数と、字の選び方
- **1回4字**（ランプ4つ）。
- 選び方（純粋関数。design-tracing.md 3.6）: まだ書いていない字を**決まった順番**で3字、書いたことがある字から1字（書いた回数が少ない字）を復習に。最初の出動は新しい字4つ。全部書き終えたら、書いた回数の少ない字から4つ。
- 順番（ひらがな）: 画数の少ない字・まっすぐな線の字から始め、まるい形・むすびのある字を後にする。
  - 1画: し・つ・く・へ・て・の・ひ・そ・ろ・る・ん
  - 2画: い・こ・り・う・と・ち・ら・え・す・よ・わ・れ・み・め・ゆ・ぬ・ね
  - 3画: け・に・か・さ・せ・も・や・お・あ・ま・は・む・を
  - 4画: た・な・き・ふ・ほ
- 順番（カタカナ）: 1画（ノ・フ・ヘ・レ）→ 2画（ア・イ・カ・ク・コ・ス・セ・ソ・ト・ナ・ニ・ヌ・ハ・ヒ・マ・ム・メ・ヤ・ユ・ラ・リ・ル・ワ・ン）→ 3画（ウ・エ・オ・キ・ケ・サ・シ・ツ・タ・チ・テ・ミ・モ・ヨ・ロ・ヲ）→ 4画（ネ・ホ）。形が似た シ・ツ と ソ・ン は、同じ出動に並べて向きの違いを見せる（矢印が役に立つ）。
- 順番（漢字）: 画数の少ない順（K8: 山・川・口 → 火・水・木・犬・手 → 石・目 → 虫・耳・糸・竹 → 花・車・足 → 雨・空 → 森）。
- 画数の合計（推奨値）: 上の順番で、ひらがな 104画・カタカナ 108画・K8 112画（KanjiVG の画数を数えた値。字ごとに教科書の画数と照合するのは W1・W3・W4。design-tracing.md 2.4）。

### 2.5 ごほうび
- 4字を書き終えたら、ほかのゲームと同じく**車のカード**（`src/ui.js:481-485` の `grantReward`）。出動の回数（`stats.sessions`）も増えるので、タイトルの窓の明かり（`src/ui.js:235`）もほかのゲームと同じに進む。
- ごほうびの画面に、**今日書いた4字**を、手本の線できれいに描いて並べる（「かけたね！」）。子どもの線そのものではなく手本の形で描く（字形がくずれていても誇らしく見え、筆跡も残さない）。
- 現場の演出: 1字書き終えるごとに、現場（かじ・たかいところ・みちのこまりごと）が1段すすむ（ほかのゲームの「正解ごと」と同じ。`stage.advance`）。
- 将来案: しゃこに「かいた もじ」のページ（書いた字がスタンプのように並ぶ）。今回は入れない。

### 2.6 声の扱い
| 時 | 読み上げ（例） | 声なしのとき |
|---|---|---|
| 字の始め | 「は。はしごしゃの は。なぞって みよう！」（例語は、もじ の単語表から `exampleOf` と同じ選び方。`src/ui.js:306-315`。無い字は字の音だけ）。漢字は K8 の読み上げ文（例「ひ。もえる ひ」。`src/data.js:218`。ひらがなだけ） | 字を大きく出し、書き順のアニメーションを1回流す |
| 画の始め | 画の番号「いち」「に」（短く。数の読み `NUM_KANA`） | 番号の丸が光る |
| 画ができた | 効果音「ぽん」（画ごとに音が上がる。`src/audio.js:108`） | 同じ |
| 大きく外れた | 最初の1回だけ「まるの ところから、もういちど」。2回目からは柔らかい音だけ（叱られている感じにしない） | 始点の丸が光り、その画のアニメーションが流れる |
| 字ができた | 「できた！ は！」 | 字が色づいて、きらきら |

- もじ と同じく、「おしい」の音は使わない（間違いではないので）。

### 2.7 iPad・iPhone での操作感（指・Apple Pencil）
- **書く板は正方形で大きく**: iPad 縦で一辺約600px、iPhone 縦で約350px（design-tracing.md 4.1）。現場は小さな帯にして、板を優先する。
- 薄い字は「道」に見える太さで出す（字の幅の約1割）。指でなぞると、色の線が手本の上に描かれる。画を書き終えると、子どもの線が**手本の形にすっと整う**（形をほめる見せ方）。
- 始点に「1」の丸、画のはじめの部分に矢印。いま書く画だけ濃く、まだの画は薄く、書いた画は色つき。
- 指でも Apple Pencil でも同じに書ける。Pencil で書いているときは、手のひらが画面に触れても線にしない（design-tracing.md 4.3）。
- 画面が動いたり拡大したりしない（板の上ではスクロール・拡大・長押しのメニューを止める）。
- iPhone の小さい画面では、許容幅を画面の大きさだけで決めず「指の太さ」の下限を持つ（3章・design-tracing.md 3.3）。

### 2.8 行き詰まらない工夫
1. **やり直しは1画だけ**。書けた画は消えない。
2. 同じ画でやり直しが続くと、助けが段々強くなる: 2回目 → その画のアニメーションを流し、許容幅を少し広げる → 3回目 → さらに広げ、しょうぼうしゃが道を先に走って「いっしょに」なぞる → 4回目 → 外れの判定をやめ、始点から終点まで進めば書けたことにする → 5回目 → 「いっしょに かけたね」と手本が書き足して次の画へ。
3. 始点でない所から書き始めたときは、線を描かず、始点の丸を光らせるだけ（やり直しに数えない）。
4. 「おてほん」ボタンで、いつでも書き順のアニメーションをもう一度見られる。
5. 時間の制限はない。ゆっくり書いても、途中で指を止めても、外れなければそのまま続く。
6. 保護者画面で「せんの はば」を「ひろめ／ふつう」から選べる（S0 は ひろめ、S1 から ふつう が既定）。
7. いつでも「やめる」（長押し。ほかのゲームと同じ）でタイトルに戻れる。

## 3. 判定の考え方（細部は design-tracing.md 3章）
- 画ごとに、(1) 手本の始点の近くから書き始めたか、(2) 指の線が手本の線から一定の距離の中にあるか、(3) 始点から終点の近くまで、手本の順に進んだか（向き）を見る。
- 「大きく外れた」は、許容幅の2倍くらい離れた所まで指が出たとき（少しのはみ出しは許す）。
- 字の形のきれいさ、はね・とめ・はらい、画の長さの比は見ない。

## 8. ユーザーに確かめること

1. **T1（最重要・ライセンス）**: 字形と書き順のデータに KanjiVG（CC BY-SA 3.0、無料）を使い、必要な字だけ変換して同梱してよいか。条件は「保護者画面とデータのファイルに出典を表示」「変換したデータのファイルは CC BY-SA で配る」。使わない場合は手作りになり、作る量と確かめる量が大きく増える（design-tracing.md 2.1）。
2. **T2**: 形は「5つめのゲーム かく」（推奨）でよいか。もじ の中の切り替え（案 B）がよいか。
3. **T3**: カタカナを S0（ひらがなの後。推奨）に置くか、S1（小1）に置くか。
4. **T4**: 関門に入れない（推奨）でよいか。
5. **T5**: 小2の漢字で、画数の多い字（例: 電 13画・線 15画）を、なぞりでは外すか。外すなら上限は何画か（推奨: 12画まで。K8 の森が12画）。
6. **T6**: 1回4字でよいか（漢字は1回の画数が多くなる。K9 だと4字で30画を超えることがある）。
7. **T7**: 書き順の照合を誰が見るか（確認用の一覧画面を設計部が用意し、最終の目視はユーザーにお願いしたい）。お手元の教科書（会社名）があれば、それに合わせる。
