## 4. 音声の単位と、文から部品への分け方（`voice.resolve`）

### 4.1 決まり

- 鍵は**読み上げ文そのもの**（前後の空白と「。」「！」「？」の直後の空白を落とし、続く空白を 1 つにしたもの。表の鍵にも入力にも同じ正規化をかける。例「ぜんぶ なぞれたね！ ひとりで かいて みよう。」の鍵は「ぜんぶ なぞれたね！ひとりで かいて みよう。」）。パックは「鍵 → ファイル名・長さ」の表。
- `resolve(text, pack)` → `[{ f, ms, gap }]`（鳴らす順。gap は前との間の ms）または `null`（端末の声で読む）。手順:
  1. 全文が表にあれば、それ 1 つ。
  2. 「。」「！」「？」の後ろで文に切る（記号は前の文に付け、後ろの空白は捨てる）。左から、**続く文をつないだものが表にあるか、長い方から探す**（「おしい！もう一回。」は 2 文だが 1 つの音声として登録してあるので 1 つになる）。
  3. 表に無い文は、型に当てはめて部品に分ける（4.2）。
  4. どれか 1 つでも解けなければ `null`（その文全体を端末の声で。混ぜない）。
- 間: 同じ文の中の部品の間 40ms、文と文の間 200ms（`GAP_PART`・`GAP_SENT`。実機で調整）。

### 4.2 型（部品に分ける文）

型の判定に使う表は `data.js` の `NUM_KANA`（`data.js:213`）・`TIME_KANA`（`data.js:391`）・`MIN_KANA`（`data.js:395`）・`AMPM_LABEL`（`data.js:385`）。

| 型 | 例 | 部品 |
|---|---|---|
| 時刻（ちょうど・はん） | `よじはん！` `出動は、よじ。` | 前置き（`出動は、` `いまは、` `ごぜん、` `ごご、`）＋時刻と記号を丸ごと（`よじはん！`）。時刻 12×{ちょうど,はん}×{。,！} = 48 |
| 時刻（それ以外の分） | `くじよんじゅうきゅうふん。` | 前置き＋`くじ`（時だけ・12）＋`よんじゅうきゅうふん。`（分と記号・58×2） |
| 式（どちらかの数が 11 以上。レベルは問わない） | `よんじゅうたすにじゅうは、いくつ？` | `よんじゅう`＋`たす`＋`にじゅう`＋`は、いくつ？`（数はふつうの読み 100 を使う） |
| 上のどれでもない | — | 丸ごと（list.js が作る） |

- 数がともに 1〜10 の式（レベルは問わない。たす 10×10=100 通り、ひく a≦10・b≦a の 55 通り。S0 の M4〜M7 に加え、S1 の M9 の 7+8 などもここに入る）、「{分}たったら、どのとけいかな？」（5 通り）、かけざんの 2 文（`ひとはこに、{a}こずつ。` 4 通り、`{m}ばこで、ぜんぶでいくつ？` 9 通り）は丸ごと作る（数が少なく、つなぎ目の無い方が自然）。丸ごとの音声があるときは型より先に 4.1 の 2 で当たる。
- 正解の `そう！{数}！` は `そう！`＋`{数}！`（1〜100 の「！」付きを作る）。

### 4.3 作る一覧（正本）は `scripts/voice/list.js`

- `units()` が、作る音声の全部を決まった順で返す: `[{ text, why }]`（why = fixed / number / time / expr / letter / trace / car など）。
  - 決まり文句は `src/lines.js` の表、組み合わせは `data.js` の表（`ALL_WORDS`・`KANJI_WORDS`・`KANJI_WORDS2`・`YOUON_WORDS`・`ALL_VEHICLES`・`SHELVES`・`STAGES`）と `strokes.js` の `SETS`（`strokes.js:149`）から全部の組を出す（乱数を使わない）。
- 同じ規則を `voice.resolve` も使うので、**テストで「全レベルの出題から出る文が、名前の文を除いて全部 `units()` だけで解ける」**ことを確かめる（13 章の T1）。これが一覧と分け方のずれを防ぐ。
- そのために、読み上げ文を作る関数（`promptText` `sayPrompt` の日本語・誤答・ヒント・正解・`tracePrompt`・`soloPrompt`・`exampleOf`・`correctExample`・`yomiOf` など）を **`src/lines.js` に移す**（PR1）。`ui.js` は `M.lines.prompt(q)` のように呼ぶだけにする。文は変えない（移す前後で、全レベルの固定シードの出題から作った全文が一致することをテストで確かめる）。

## 5. 再生（`src/voice.js`）

### 5.1 形

`create(env)`。env: `context()`（audio.js の AudioContext を返す。無ければ null）、`fetch`、`loadScript(url, cb)`、`setTimeout`、`protocol`。Node のテストは偽の env を渡す（`speech.js:3` と同じやり方）。

| 関数 | 中身 |
|---|---|
| `select(id)` | `voice/<id>/index.js` を script 要素で読む（`Manabi.voicePack({...})` で登録される）。状態: none → loading → ready / failed |
| `ready()` | パックがあり、`protocol` が http(s) で、AudioContext が running |
| `plan(text)` | `resolve(text, pack)` |
| `prefetch(texts)` | 文を `plan` して、まだ持っていない音声を読んで復号しておく |
| `play(plan, hooks)` | 鳴らす。hooks: `onstart` `onend` `onerror(why)` |
| `stop()` | 鳴っている・予約した音を全部止める（`AudioBufferSourceNode.stop()`） |

### 5.2 鳴らし方

- AudioContext は効果音と同じものを使う（`audio.js` に `context()` を足して `ensure()` の結果を返す）。iOS は AudioContext を最初のタップの中で動かさないと鳴らず、2 つ目を作ると止まったままになりやすい。今は `unlockOnce`（`ui.js:252-256`）が毎タップ `A.unlock()` を呼んで resume を試みているので、そのまま乗れる。
- 声の音量は声用の GainNode を 1 つ通して `destination` へ（効果音のコンプレッサー `audio.js:23-33` は通さない。効果音と声で音量を別に扱えるように）。
- 部品は `start(when, offset, duration)` で、前の部品の終わり＋gap に予約してつなぐ（隙間がそろう）。`playbackRate` は変えない（高さも変わるため。速さは書き出しで決める）。
- **頭とおしりの無音を切る**: 復号したときに、先頭と末尾の「振幅 0.004 未満が続く所」を測って offset・duration に入れる（AAC は頭に約 2,112 サンプルの無音が入り、VOICEVOX も前後に無音を付けるため。つなぎの間を 4.1 の値にそろえる）。
- `onend` は最後の部品の `onended`。来ない端末に備え、予定の長さ＋1 秒で終わったことにする。

### 5.3 読み込みと遅れ

- 生のファイル（数 KB）は、読んだものを全部メモリに置く（1 回の起動で多くて 1〜2MB）。**復号した音（AudioBuffer）は数を絞る**: iOS は 48kHz で復号するので 1 秒あたり約 192KB。全部（約 1,500 秒）を復号すると約 290MB になり持てない。復号済みは新しい順に 80 個まで（約 15〜20MB。`DECODED_MAX`）。`decodeAudioData` は渡したバッファを使えなくするので、生のファイルは複製して渡す。
- 先読みの時機:
  - 声を選んだとき・最初のタップのあと: 決まり文句（「出動！」「そう！」「おしい！もう一回。」「こっちかな？」「どれかな？」「だれが遊ぶ？」「どれで出動する？」など約 30）。
  - 出動を始めるとき（`ui.js:305` `startSession`）: 4 問ぶんの問題・正解・各誤答・ヒント・数え聞かせの文（`lines.js` に `sessionTexts(qs)` を足す）。30〜60 ファイル・数百 KB。
  - 「かく」を始めるとき（`ui.js:588` `launchTrace`）: 4 字ぶんの文。ごほうび画面の前: もらう乗り物の文。
- 鳴らす時に音がまだ無いとき: 最大 0.8 秒（`CLIP_WAIT_MS`）待つ。間に合わなければ `onerror('late')` を返し、speech.js がその文を端末の声で読む（何も鳴っていないときだけ）。

### 5.4 失敗

- 読めない（404・通信なし）・復号できない・AudioContext が動かない、が 3 回続いたら（`FAIL_MAX`）状態を failed にし、その起動の間は端末の声だけにする（`onChange` で画面に知らせる。保護者画面の注意書き 7.1）。
- 表に無い文（`resolve` が null）は失敗に数えない。`#debug` のときは `#errlog`（`docs/design.md:77`）に「声のファイルが無い文」として出す（作り漏れに気づくため）。

## 6. speech.js との互換

### 6.1 API はそのまま

`init` `speak(text, opts)` `speakSeq(items, opts)` `cancel` `available` `isVoiceless` `enAvailable` `setEnabled` `onChange` `forceVoiceless` `forceNoEnglish` `reason` `enReason` `pickVoice`（`speech.js:171-175`）は名前も引数も変えない。足すのは:

- `opts.alt`（名前の文の代わりの文。3.3）
- `prefetch(texts)`・`setSpeaker(id)`・`speaker()`（どの声で読んでいるか: 'device' / パックの id）

### 6.2 1 つの文を読む順

`speak(text, opts)`（日本語）:
1. 音声ファイルの声を選んでいて `clips.ready()` かつ `clips.plan(text)` がある → それで鳴らす。`onerror` が来たら 2 へ。
2. Web Speech の日本語が使える → 今の `speakRaw`（`speech.js:96-120`）。
3. `opts.alt` があり `clips.plan(opts.alt)` がある → それで鳴らす。
4. どれも無い → false を返す（今と同じ）。

`speakSeq` の各項目は、日本語なら上の 1〜3、英語なら今どおり Web Speech。`gap`・英語が 3 秒始まらなければ飛ばす（`speech.js:155`）・15 秒の保険（`speech.js:156`）は今のまま。音声ファイルで鳴らした項目は `onstart` がすぐ来るので、長さの見積もりでの打ち切り（`speech.js:153`）は音声の長さ＋1 秒に置き換える。

### 6.3 声なしモード

- `available()` = 「`clips.ready()`」**または**「Web Speech の日本語が使える（今の `avail('ja')`）」。どちらも駄目なときだけ声なし（`isVoiceless()`）。
- これで、Web Speech が無い端末でも音声ファイルが鳴れば、声なしの手当て（1 回目の誤答で正解を光らせる、`ui.js:454`）が要らなくなる。表に無い文（名前の文の alt も無いとき）は黙る。作り漏れは T1 のテストで防ぐ。
- 1.5 秒で声を探す判定（`speech.js:79-82`）は Web Speech の判定としてそのまま残す。
- 「読み上げ」オフ（`setEnabled(false)`、`speech.js:92`）は音声ファイルも止める。

### 6.4 `file://`

- `file://` では fetch・XHR でファイルを読めない（Chrome は不可、Safari も設定次第）。`decodeAudioData` には中身のバイトが要るので、Web Audio では鳴らせない。
- **推奨: `file://` では `clips.ready()` を false にして、今と同じ端末の声で遊ぶ**（パックの script は読めるが使わない）。保護者画面の「こえ」に「ファイルで ひらいているので、たんまつの こえに なります」と出す。
- 手元で VOICEVOX の声を確かめるときは `python3 -m http.server 8000` で開く（README に書く）。
- 将来 `file://` でも鳴らしたくなったら、`<audio>` 要素 1 つを使い回す案（つなぎ目はそろわない）を足す（15 章）。

## 7. 声の選び方と保存

### 7.1 保護者画面（`index.html:176-183` の「おと」）

- 「こえ」: 選べる声をボタンで並べる。`たんまつの こえ` ＋ `voice/voices.js` にある声（例 `めたん（VOICEVOX）`・`ずんだもん（VOICEVOX）`）。選ぶと保存し、その声で `こんにちは。はたらくまなびです。` を読む（「よみあげテスト」`ui.js:1500-1503` も選んだ声で読む）。
- 注意書き（`p-voice-note`）: `file://` のとき／読み込みに失敗して端末の声で読んでいるとき／声なしのとき。

### 7.2 保存（端末ごと）

- `device.sound.speaker`（文字列）。`''` = おまかせ（`voices.js` の先頭の声、無ければ端末の声）、`'device'` = 端末の声、それ以外 = パックの id（小文字の英数字とハイフン 20 字まで）。
- `normalizeSound`（`storage.js:119-122`）が、無い・形が違う値を `''` にする。保存データの版は変えない（足すだけ。とけいのときと同じやり方 `docs/design.md:59`）。
- 一覧に無い id（声を減らした）が入っていたら、おまかせとして扱う（保存は書き換えない）。

### 7.3 子どもごとにしない理由

効果音・読み上げのオン/オフと同じく、音は端末と場所の都合（`docs/design-elementary.md:80`）。子どもごとにすると、子どもを替えるたびにパックを読み替え、先読みも捨て直しになる。兄弟で声を分けたい要望が出たら、プロフィールに `speaker` を足し、`useProfile`（`ui.js:38`）で `setSpeaker` する形で足せる。

### 7.4 既定

おまかせ（＝1 人目の声。推奨は四国めたん）。Web で開いて音声が読めるときだけ VOICEVOX の声、それ以外は黙って端末の声。

## 8. 形式と大きさ

### 8.1 形式

| 形式 | 実測（macOS の `say` で作った 24kHz・1ch の WAV を afconvert で変換。2026-10-27） | 評価 |
|---|---|---|
| m4a（AAC-LC 32kbps、`afconvert -f m4af -d aac -c 1 -b 32000`） | 4.42 秒 → 23.7KB、0.52 秒 → 6.6KB。**1 ファイルに約 3.2KB の空き（free 箱）と約 0.9KB の目次（moov）** が付く | iOS で確実。1,200 ファイルだと空きだけで約 5MB 増える |
| **ADTS（AAC-LC 32kbps の .aac、`afconvert -f adts -d aac -c 1 -b 32000`）** | 0.52 秒 → 2.6KB | **推奨**。いちばん小さく、箱の作り直しも要らない。iOS Safari・Chrome の `decodeAudioData` で読めるかを PR2 の実機確認で 1 ファイルだけ試す |
| m4a から free 箱を取る（build.js で stco を詰め直す） | 約 1KB の上乗せ | ADTS が実機で駄目だったときの代わり |
| MP3 | — | macOS に標準のエンコーダが無い（lame・ffmpeg を Homebrew で足すことになる）ので採らない |

- 1 人あたり: 約 1,500 秒 × 約 4KB/秒 ≈ **約 6〜6.5MB（ADTS）**、m4a のままだと約 11MB、free を取った m4a で約 7.5MB。2 人で約 13〜15MB。
- 音量は書き出しで `volumeScale` をそろえる（afconvert は音量をそろえない）。サンプリングは VOICEVOX の 24kHz のまま。

### 8.2 上限

- GitHub Pages: 公開サイトは 1GB まで、帯域の目安は月 100GB（https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits）。
- リポジトリ: 1GB 以下を推奨、50MB を超えるファイルは警告、100MB を超えるファイルは置けない（https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github）。
- 今のリポジトリは約 9MB。2 人の声で約 25MB。書き直しは変わった文だけ（10.4）なので、文言を少し直すたびに数 KB〜数十 KB しか増えない。声を作り直す（声の高さ・速さを変える）と 1 人あたり約 6MB が履歴に積まれるので、声の設定は聞き比べで先に決める。
- テストで、`voice/` 全体 40MB 以下・1 ファイル 300KB 以下を確かめる（13 章の T7）。
- Git LFS は使わない（Pages の公開で別の手当てが要り、無料枠の帯域も小さい）。

## 10. 書き出しのしくみ

### 10.1 VOICEVOX エンジンを手元の Mac（arm64）で動かす

Homebrew の cask は無い。どちらも無料。

| 方法 | 手順 | 評価 |
|---|---|---|
| **A. アプリ版（推奨）** | https://voicevox.hiroshiba.jp/ から `VOICEVOX.0.26.1-arm64.dmg`（2026-10-23 公開）を入れて起動する。起動している間、エンジンが `http://127.0.0.1:50021` で待つ | 画面で聞きながらアクセントを直せる（10.3）。追加の依存なし |
| B. Docker | `docker run --rm -p 127.0.0.1:50021:50021 voicevox/voicevox_engine:cpu-arm64-0.26.0`（Docker Hub に arm64 の安定版タグあり。2026-10-23 更新） | 画面が要らない。Docker Desktop は個人・小規模事業なら無料（大企業は有料） |
| C. エンジン単体 | GitHub Releases の `voicevox_engine-macos-arm64-0.26.0.7z.001`（2026-10-19）を展開して `run` | A・B で困ったとき |

- 動いているかは `curl http://127.0.0.1:50021/version`。API の説明は `http://127.0.0.1:50021/docs`。
- 外へは聞かせない（`127.0.0.1` に限る）。

### 10.2 `scripts/voice/build.js`（Node の標準機能だけ。`fetch`・`crypto`・`fs`・`child_process`）

`node scripts/voice/build.js --voice metan [--engine http://127.0.0.1:50021] [--all] [--prune] [--dry-run]`

1. `GET /version` と `GET /speakers` で、`voices.json` の `uuid`＋スタイル名からスタイル id を引く（id を決め打ちしない）。無ければ止める。
2. `scripts/voice/dict.tsv`（語・読み・アクセント）を `POST /import_user_dict?override=true` で入れる（エンジンの辞書を毎回リポジトリの表と同じにする）。
3. `list.units()` の各文について、鍵 = `sha256(文 + 読みの直し + スタイル + パラメータ + 辞書の表のハッシュ)` の先頭 12 桁。パックに同じ鍵があり、ファイルもあれば作らない（`--all` で全部作り直す）。
4. `POST /audio_query?text=…&speaker=…` → パラメータを上書き → 読みの直し（10.3）があれば `POST /accent_phrases?text=<読み>&speaker=…&is_kana=true` の結果で `accent_phrases` を置き換え → `POST /synthesis?speaker=…` → WAV。
5. WAV を一時フォルダ（`os.tmpdir()`）に置き、`afconvert -f adts -d aac -c 1 -b 32000 in.wav voice/<id>/<鍵>.aac`。長さは WAV の頭から計算する。
6. `voice/<id>/index.js`・`voice/<id>/README.md`・`voice/voices.js` を書く。`--prune` で一覧に無いファイルを消す。
- 1 文ずつ順に（並べるとエンジンの CPU を取り合う）。1,200 文で 10 分前後の見込み（未計測）。
- 作った WAV はリポジトリに置かない。

### 10.3 読みの直し

- まず読み上げ文そのものは変えない（Web Speech 向けに漢字・カタカナまじりにしてある。`docs/design.md:27`）。VOICEVOX が読み違える所だけ直す。
- **単語**（何度も出る語）: `dict.tsv` に `出動	シュツドウ	3`（表記・カタカナの読み・アクセント核の位置）のように書く。候補: 出動・一回・遊ぶ・最初・時間 など。
- **文ごと**: `yomi.tsv` に `文 <TAB> AquesTalk 風の読み`（カタカナ、`'` がアクセント核、`/` が句の区切り、`、` が間）。今の読みは `node scripts/voice/build.js --kana "はしごの は。"`（`audio_query` の結果の `kana` を出す）で見て、直して貼る。アプリ版の画面で聞きながらアクセントを動かし、良かった形をこの書き方に写す。
- **必ず聞いて確かめる所**（Web Speech で揺れた所。`docs/design.md:27`）: 文字の音の「は」「へ」（「はしごの は。」「は！」が わ・え にならないか）／時刻の よじ・しちじ・くじ・〜ふん/ぷん／数の よん・なな・きゅう／「もう一回」（いっかい）／〜しゃ の語／漢字の読み上げ文（「ひ。もえる ひ」）。
- 聞いて確かめた文は `yomi.tsv` に「確認済み」の印を付け、どこまで聞いたかを残す。

### 10.4 記録

- パック（9.1）に、エンジンの版・スタイル（uuid・名前・id）・パラメータ・作った日。各文の鍵に読みの直しと設定が入っているので、何を変えたらどの音声が変わるかが追える。
- `voice/<id>/README.md` に、規約の URL と確認日（書き出すたびに規約のページを見直して日付を更新する）。

### 10.5 聞き比べ（`scripts/voice/sample.js`）

`node scripts/voice/sample.js --voices metan,zundamon,himari,hau,sora,kurono --out ~/Desktop/voice-sample` で、候補ごとに同じ 8 文（「出動！」「よじはん。どのとけいかな？」「はしごの は。おしい！もう一回。」「そう！ななじゅうご！」「くじ」＋「よんじゅうきゅうふん。」のつなぎ、など）を WAV で書く。**リポジトリの外に書く**（コミットしない）。ユーザーが聞いて声とパラメータ（速さ 0.9〜1.0、抑揚）を決める。

## 13. テスト観点（Node。`tests/`）

- **T1 網羅**: 全レベル（`P.LEVELS`）× 固定シードで 1,000 回ずつ出題し、`lines.js` で作った全部の日本語の文（問題・正解・全誤答・ヒント・数え聞かせ）と、かく の全字の文、乗り物・棚・階級・めんきょ・決まり文句が、`list.units()` だけの表で `resolve` が null を返さない。名前の文は除き、その alt が解けることを確かめる。

## 14. 実機確認（PR3。iPad・iPhone の Safari が主）

8. 声を切り替えた直後のテスト読み、端末の声への切り替え。

| 文ごとに全部作る（3.2 の A） | 1 人約 36MB。声を足すたび・文言を直すたびに重い |
| 「。！？」で機械的に切るだけ（B） | 約 22MB。時刻×2 通りの記号が残り、「おしい！」「もう一回。」が別の音声になって不自然 |
| 1 つのファイルにまとめる（スプライト） | 全部を復号すると iOS で約 290MB。1 文直すたびに大きなファイルが履歴に積まれる |
| ゲーム・レベルごとのスプライト | メモリは抑えられるが履歴の問題は同じ。数・時刻の部品を共有できない |
| base64 で js に埋める（`file://` でも鳴る） | 3 割大きくなり、声ごとに数 MB の js を起動時に読む |
| `<audio>` 要素で鳴らす（`file://` でも鳴る） | iOS で遅れが大きく、つなぎ目がそろわない。`file://` 用の将来案として残す |
| その場で合成する（VOICEVOX をサーバーに置く・有料の音声合成 API） | 外部依存・費用・オフラインで使えない・子どもの画面の文を外へ送る |
| 名前を 1 文字ずつつなぐ／名前だけ端末の声 | 不自然／1 つの文の中で声が変わる |
| 子どもごとに声を持つ | 7.3 |

### PR2

- `audio.context()` は**作らず**、あれば AudioContext を返すだけ（設計は `ensure()` の結果）。`ensure()` だと `available()` を呼んだだけで最初のタップの前に作られ、audio.js の「最初のタップの前には作らない」が崩れるため。作るのは今までどおり `unlock()`。
- `voice/voices.js` が空の間は、`speech.setSpeaker` が声を選ばない（`voice/<id>/index.js` を読みに行かない）。404 のエラーを出さないため。`speaker()` は `'device'`。
- `normalizeSound` に `speaker` を足したので、`tests/storage.test.js` の `device.sound` の完全一致 4 か所に `speaker: ''` を足した（形が変わったため。他の検査は変えていない）。
- 失敗の数え方（5.4）: パックが読めない・ファイルが読めない（404・通信）・復号できない、を数える。「間に合わない（late）」と、AudioContext が止まっていて `ready()` が偽のときは数えない。成功したら数え直す。
- `onMiss`（作り漏れ）は `speech.js` が持ち、`#debug` の `main.js` が `#errlog` に「声のファイルが無い文」を出す。alt のある名前の文は知らせない。
- 声のパックを読み込めたとき、決まり文句（`lines.FIXED` の全部）を先読みする（`warm`）。先読みは、出動の始め（`startSession`）・かくの始め（`launchTrace`）・ごほうび画面（もらう乗り物か ごほうびステッカー）。字の札・しゃこの文は先読みしない（0.8 秒待って間に合えば鳴る）。
- 音声ファイル（ADTS）は Chrome の `decodeAudioData` で、macOS の `say` から作った 1 声ぶんの一時のパック（リポジトリには入れない）を使って、鳴ることを確かめた。iOS Safari・iPad の実機は未確認（PR3 の実機確認 14 章）。
