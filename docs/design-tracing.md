### 2.3 データの形（`src/strokes.js`。classic script、`window.Manabi.strokes` / `module.exports`）

```js
// 形の例（実装の目安。座標は KanjiVG の 109×109 を 10 倍した整数 0〜1090）
STROKES = {
  'し': { s: [[391,175, 403,206, 399,242, 395,277, ...]], n: [[309,141]], t: ['㇙'] },
  ...
}
SETS = { hira: 'しつくへてのひそろるん…', kata: 'ノフヘレ…', k1: '山川口…', k2: '…' }   // 2.4 の順番
```

- `s`: 画の配列。1 画は `[x0, y0, (c1x, c1y, c2x, c2y, x, y) × 区間の数]`。KanjiVG の `M/C/c/S/s/L/l` を、すべて絶対座標の 3 次ベジェに直す（直線は制御点を線の上に置く）。描くときは `bezierCurveTo` をそのまま使え、判定のときは 3.2 で点列にする。
- `n`: 画の番号を置く位置（KanjiVG の `<text>` の座標）。重ならないよう作られているので、そのまま使う。
- `t`: 画の種類（KanjiVG の `kvg:type`。㇐ 横・㇑ 縦・㇒ 左はらい など）。描画には使わず、テスト（2.4 の向きの検査）にだけ使う。
- `SETS`: なぞる順番（企画 2.4）。漢字の `k1` は `KANJI_WORDS` の字と同じ集合（テストで検査）、`k2` は R3 で決まる K9 の字から T5 の上限で選ぶ。
- 大きさ: ひらがなの元の path は約 13KB。全部で約 480 画なので、整数の配列で **約 60KB**（未圧縮）。`index.html` で `trace.js` の前に読む。
- 濁点・半濁点・小さい字は持たない（将来案。企画 7章）。

## 3. 判定

### 3.1 座標
- 板（正方形）の一辺を 1 とする正規化座標 `(x, y)`（0〜1、左上が 0）。データは `/1090` して使う。
- 指の座標は `pointerdown` のときに板の `getBoundingClientRect()` を一度だけ測り、`(clientX − left) / side` で直す。
- 許容幅などは正規化座標の長さで持ち、画面の大きさ（px）による下限は UI 側で換算して渡す（3.3）。判定の関数は px を知らない。

### 3.2 手本の点列（純粋関数 `strokePolyline(stroke, h)`）
- 3 次ベジェを細かく区切って折れ線にし、**弧長で等間隔 h（= 0.01）に打ち直す**。始点と終点は必ず含める。ひらがなの 1 画（長さ 0.3〜1.5）で 30〜150 点。
- 字を出すときに 1 回だけ作り、字の間は使い回す。判定はこの点列だけを使い、ベジェは扱わない。

### 3.3 許容幅（推奨値。`T.DEFAULTS` に定数で持ち、実機で調整する）

板の一辺を B（CSS px）、幅の倍率を k（`ふつう` 1.0・`ひろめ` 1.3、`auto` は S0 が ひろめ・S1 以降が ふつう）、漢字は形が細かいので g = 0.85、かなは g = 1。

| 名前 | 意味 | 値（正規化） | iPhone 縦 B=350 / iPad 縦 B=600（ふつう・かな） |
|---|---|---|---|
| `near` | 手本の点を「通った」とみなす距離 | `max(0.065·g, 22/B)·k` | 23px / 39px |
| `off` | これより遠いと「外」 | `max(0.15·g, 48/B)·k` | 53px / 90px |
| `offRun` | 「外」がこの長さ続いたら**大きく外れた**としてやり直し | `0.04` | 14px / 24px |
| `startR` | 書き始めを始点とみなす距離 | `max(0.10, 34/B)·k` | 35px / 60px |
| `endP` | 指を離したとき、これだけ進んでいれば書けた | 進度 0.90 | — |
| 見せる「道」の太さ | 薄い字の線の太さ | `0.10·k`（漢字 `0.08·k`） | 35px / 60px |

- **px の下限の根拠**: 子どもの指先の幅は約 8〜10mm。iPhone では 1 CSS px が約 0.16mm、iPad では約 0.19mm なので、指の幅は 40〜60 CSS px。指の真ん中と手本の線のずれは指の幅の半分くらいまで起きる、と見て `near` の下限を 22px、`off` の下限を 48px とした。板が小さいほど比率は下限の方に寄り、**iPhone でも判定が厳しくならない**。
- 「少しのはみ出し」（near〜off の間）は許す。進度は進まないが、やり直しにもならない。
- 漢字（森・雨など）は画と画の間が 0.08〜0.1 しかないことがある。`off` が隣の画まで届いても、進度は「いま書いている画の、いまの進度の前後」でしか進まない（3.4）ので、隣の画をなぞっても書けたことにはならない。

### 3.4 1 画の判定（純粋関数。状態を受け取り、新しい状態を返す）

```
beginStroke(poly, p, tol)        → { state, result: 'started' | 'reverse' | 'miss' }
moveStroke(poly, state, pts, tol) → { state, result: 'ok' | 'off' }
endStroke(poly, state, tol)      → { result: 'done' | 'short' | 'off' }
```

- `beginStroke`: 押した点が始点から `startR` の中 → `started`。終点の近く（`startR` の中）で始点から遠い → `reverse`（逆向き。始点の丸と矢印を光らせる）。それ以外 → `miss`（線を描かず、始点を光らせる）。`reverse`・`miss` は、続けて 2 回まではやり直しに数えない（2.8-3）。3 回目から数える（3.6）。
- `moveStroke`: 受け取った点を 1 つずつ、直前の点との間を `near/3` の間隔で補って（3.5）、次を行う。
  1. **進度つき最近傍**: いまの進度 `idx` から先の窓 `[idx, idx+W]`（W は長さ 0.12 ぶん、h=0.01 で 12 点）の中で、点から `near` 以内にある一番先の手本の点 `j` を探し、`idx = max(idx, j)`。窓より先には飛ばない。
  2. **外の判定**: 手本の線分のうち `[idx−W, idx+W]` の範囲だけとの距離 d を測る。d > `off` なら外の長さを足し、そうでなければ 0 に戻す。外の長さが `offRun` を超えたら `off`（大きく外れた）。
  - **near〜off の間を続けてなぞるとき**（実装 W1）: 進度 `idx` は進めないが、「外」の判定の窓の中心は別の位置 `ref`（near〜off の間でも、窓の中で一番近い手本の点まで進める）に置く。これで、少しずれたまま最後までなぞっても `off` にならない（進度が進まないので `short` になり、助けの段階で幅が広がる）。
  - **輪の近道の防止は W1 では限定的**（実装 W1）: 進度の窓は `idx`・`ref` の先 2W（0.24）、「外」の窓は `ref` の前後 W。**小さい輪の近道（る・て・そ・ん・え、wide・助けでは ろ・わ・れ・ゆ・ね・を も）は防がない**。「正しくなぞる子を止めないこと」を近道の防止より優先するため（進度に「指の道のり＋near」の上限を付ける案は、の を 0.9·near 内側へずらす・内側へ 0.03〜0.05 ずらす・0.85 倍・角を丸めた そ・速い指で、正しくなぞっても short にしたので外した）。大きい輪（の・ぬ・あ・め・ね・お・ま・み・よ・な を、ふつう・ひろめ、助け m≤1）の近道は窓で防げ、`tests/trace.test.js` の 6 で確かめる。将来防ぐ仕組みは、同 14（正しくなぞる場面: ±0.9·near、全 104 画を ±0.03〜0.05、0.85 倍、丸めた そ、点の間 0.25 の速い指 × normal/wide × m=0〜4 がすべて `done`）を通ることが条件。候補は、手本の点のうち指が near 以内に来た割合（カバー率）で、W2 の実機調整で既定オフの候補として試す。
  - 窓を進度の前後に限るので、**輪や交差のある画**（あ の 3 画目、の、ぬ・ね の 2 画目、め・る・ろ）でも、交差点で反対側の手本に吸い寄せられて進度が飛ぶことがない。窓が無いと、の の交差点で一気に終点の近くまで進み、輪を書かずに終われてしまう。
  - 逆に戻っても、`idx` は減らず（単調）、戻った分はやり直しにもならない。
- `endStroke`: 大きく外れたあとは `off`（二重に数えない）。`idx ≥ endP·(点の数−1)` → `done`、それ以外 → `short`（途中で離した。同じ画をもう一度）。
- **短い画（点）**: 長さが 0.08 未満の画（ひらがなには無い: 最短は お の 3 画目で 0.182、ふ の点も約 0.25。点の実データを使うのは W4 の漢字の 火 の 1・2 画、K9 の 、など。W1 のテストは合成データで確かめた）は、始点だけでなく画のどこから押しても `started` とし、押した点と離した点がどちらも `off` の中なら、動きが小さくても（ちょんと触っただけでも）`done`。点の向きは見ない。
- 向き: 始点から始め（`beginStroke`）、進度が始点から終点へ単調にしか進まない（`moveStroke`）ので、向きは自然に守られる。はね・とめ・はらいは見ない。

### 3.5 速い子・ゆっくりの子
- **速い子**: Safari（iPadOS）の pointer events は `getCoalescedEvents()` に対応していない（2026-10-26 時点の開発者の報告。出典 8章）。速くなぞると `pointermove` の点がまばらになるので、**直前の点との間を `near/3` ごとに直線で補ってから**判定する。点ではなく線分で外れを見ることになり、まばらでも曲線の内側を近道（弦）した分は `off` で正しく外れになる。`getCoalescedEvents` がある環境ではそれも使う（あれば点が増えるだけ）。
- **ゆっくりの子**: 時間の制限は持たない。止まっていても外の長さは増えない（同じ点が続くだけ）。1px 未満の動きは捨てて点を増やさない。指を置いたまま 8 秒進まないときは、その画のアニメーションを 1 回流す（声は出さない）。
- 指の線（見せる線）は補った点ではなく、受け取った点をそのままつなぐ（見た目が速さで変わらない）。

### 3.6 助けの段階（行き詰まらない工夫。企画 2.8）
画ごとに「やり直しの回数」m を数える（`off` と `short` の合計。`reverse`・`miss` は 3 回目から数える）。**二重に数えない約束: UI は `endStroke` の戻り値だけを `recordAttempt` に渡す。`moveStroke` の `off` は数えない**（`off` になった画は `endStroke` も `off` を返すので、指を離したときに 1 回だけ数える）。

| m | 助け | 判定の変化 |
|---|---|---|
| 0 | なし | 3.3 のまま |
| 1 | 始点の丸が光る。声は字の中で最初の 1 回だけ「まるの ところから、もういちど」 | なし |
| 2 | その画のアニメーションを流す | `near`・`off` を ×1.25 |
| 3 | しょうぼうしゃが道の先を走り「いっしょに」（車について行けばよい） | ×1.5 |
| 4 | 何も言わない | `off` を見ない（始点から終点まで進めば書ける） |
| 5 以上 | 「いっしょに かけたね」と手本がその画を書き足す | その画は書けたことにして次の画へ |

- `reverse`・`miss` が同じ画で 3 回続いたら、その画のアニメーションを流す。**3 回目から先は 1 回ごとに m にも数える**（始点を光らせても押せない子も、必ず m=5 の手本の書き足しに届く。`recordAttempt`）。
- 1 字の中で m が 1 以上の画があれば、その字は `clean` に数えない（記録だけ）。

### 4.2 canvas の層と描画（`src/traceboard.js` の `TraceBoard`）

- **指の canvas**（上）: いま書いている線だけ（青 `#1e6fe0`、太さ `0.05·B`、丸い端）。`pointermove` ごとに前の点からの線を足すだけにして、全体を描き直さない（遅れを小さくする）。画が終わったら消す（書けたら手本の canvas に赤い手本の形が出る＝「すっと整う」）。

- 指の線は手本より細くして、手本の道が指の線の下から見えるようにする。

### 4.3 pointer events
- 板の要素（2 枚の canvas を包む div）で `pointerdown`・`pointermove`・`pointerup`・`pointercancel`・`lostpointercapture` を受ける。`pointerdown` で `setPointerCapture`（`src/ui.js:226` と同じ）。
- **追うのは 1 本だけ**: いま追っている pointer がある間は、ほかの `pointerdown` を無視する（2 本目の指・手のひら）。
- **Apple Pencil と手のひら**: 
  - ペン（`pointerType === 'pen'`）で書いている間は、指（`touch`）を無視する。ペンを離して 600ms の間も無視する（手のひらが残るため）。
  - 指で書き始めた後にペンが触れたら、指の画を**黙って取り消し**（やり直しに数えない）、ペンに切り替える（手のひらが先に触れて、そのあとペンが来る場合）。
  - ペンを浮かせたときの `pointermove`（ホバー。ボタンが押されていない）は無視する。筆圧は使わない。
- `pointercancel`・`lostpointercapture`（端末に取り消された）は、指を離したのと同じに扱う。ただしその結果が `short` なら、やり直しに数えない（子どものせいではないため）。
- マウス（PC での確認）も同じ流れで動く。

### 4.4 スクロール・拡大の抑止
- 板と 2 枚の canvas に `touch-action: none`（長押しボタンと同じ流儀。`css/style.css:37-38`）。`pointerdown` で `preventDefault`。
- iOS の Safari は `user-scalable=no`（`index.html:5`）を守らず指 2 本で拡大できるので、`s-trace` が出ている間だけ `gesturestart`・`gesturechange`（WebKit のイベント）で `preventDefault` する。
- 長押しのメニュー・虫めがね・文字の選択は、全体の `-webkit-touch-callout: none`・`user-select: none`（`css/style.css:5`）に加え、板で `contextmenu` を止める。
- 画面の端のスワイプ（Safari の戻る）は止められない。板の余白と、ホーム画面に追加して遊ぶこと（保護者画面で今も勧めている）で避ける。
- iPadOS の手書き入力（スクリブル）は文字の入力欄だけに働くので、canvas では起きない（入力欄を置かない）。

### 4.5 番号と矢印
- 番号: KanjiVG の番号の位置（`n`）に丸（半径 `0.045·B`）と数字。いま書く画は緑で大きく、ゆっくり脈打つ。まだの画は小さな灰色。書けた画の番号は消す。
- 始点: いま書く画の始点に緑の丸（`startR` の大きさの薄い円も重ねて、ここから押せばよいと分かるように）。
- 矢印: いま書く画だけ、始点から長さ 0.12 進んだ所に、接線の向きの「く」の字の矢じり。長い画（0.5 以上）は真ん中にもう 1 つ。輪のある画は、輪に入る手前にも 1 つ。
- 数字はシステムのフォント（`Hiragino Maru Gothic` など、`css/style.css:4` と同じ）で描く。外部フォントは使わない。

### 4.6 ヒント（1 画ずつのアニメーション）と流れ
- アニメーション: 画ごとに、番号が出て、筆の点が始点から終点へ手本の線を橙で塗る。1 画の時間は `clamp(長さ × 1.6 秒, 0.35, 1.2)`、画の間 0.25 秒。漢字の 1 字ぶんは 1.5 倍速。流れている間に板をタップすると最後まで飛ばす（入力はそこから受け付ける）。`prefers-reduced-motion` のときは、しょうぼうしゃを動かさず、線の塗りだけにする。
- **字の始め**: 字を大きく薄く出す → 声（企画 2.6）→ その字を初めて書くとき（`done[字]` が 0）だけ全画のアニメーション（T8）→ 1 画目の番号と始点が光る。
- **画**: `started` → 指の線 → `done`（`pon`、手本の形が赤く出る、次の画の番号が光る）/ `off`（指の線が薄く消える、柔らかい音、3.6 の助け）/ `short`（同じ）。
- **字ができた**: 字全体が赤く色づいてきらきら、`correct` の音、「できた！ は！」、ランプが 1 つ点く、現場が 1 段すすむ。`trace.done[字]` をすぐ足して保存（途中でやめても、書けた字は数える）。2.3 秒後に次の字。
- **4 字目のあと**: `stats.sessions`・`stats.trace.sessions`・`chars`・`clean` を足し、`grantReward`、`lastPlayed`、保存、ごほうび画面。`afterSession`（階段）は呼ばない。ごほうび画面の下に今日の 4 字を手本の形で並べる（小さな canvas。`run.game === 'trace'` のときだけ）。
- 「もういちど」（ごほうび画面）は、なぞりから来たときは なぞりをもう一度始める。
